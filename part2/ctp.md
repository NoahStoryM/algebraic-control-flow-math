## 素材与文献

第一部正文不提 Haskell，这张对照表留给第二部。Haskell 只在一个范畴（类型与函数）里干活，把范畴论的概念做成类型类接口；Noah 还没有学 Haskell，打算直接学 Agda。

用范畴论的三种做法（Claude 10/7 的分法），说明第一部与 CTP 各在哪里：

- **描述**：把范畴、函子当数据写出来，任何语言都行。CTP 初版属于这一种。同类工作：Rydeheard 与 Burstall《Computational Category Theory》（ML）、Catlab（Julia）、DisCoPy（Python）、agda-categories、Lean 的 mathlib。
- **组织**：用范畴论的概念当接口来组织程序，Haskell 的做法。
- **解释**：用范畴论说明语言特性是什么意思，即语义学。第一部属于这一种。

要接上的文献（都是 Claude 凭记忆列的，用之前要查原文）：

- Danvy 与 Filinski《Representing Control》1992：用 `shift` / `reset` 写直接风格的一遍 CPS 变换，与第四篇擦除 `ctx` 那一步是同一件事。
- Moggi 的计算 λ 演算、Filinski《Representing Monads》、Plotkin 与 Power 的代数效应：第六、七篇要接的语义学文献。

### 栈、自由范畴与自由单子

4 月到 7 月讨论过的一条线，10/7 从旧对话里找回。它的代码一侧归第七篇（见「伏笔与线索」），起名字的一侧归这里。都是当时讨论的结论，没有对照文献核过。

- **栈是自由范畴的态射**：把延续单子的 Kleisli 范畴看作图，栈是图上的一条路径，即待复合箭头的列表；复合是拼接，`apply-cont` 是从自由范畴回到真实 Kleisli 范畴的求值函子。CTP 初版 2.1.11 已经讲了自由范畴与路径。
- **自由单子是多孔的推广**：每个操作恰好一个延续孔时，树退化成列表，也就是栈；`amb` 的 Choose 两个孔、Fail 零个孔，就成了树。Noah 当时想从 Kleisli 范畴的自由范畴去理解自由单子；结论是出发点没错，得到的是单孔特例，自由单子的递归发生在 F-代数那一层。
- **两次「变成数据」**：自由范畴只把「怎么串」推迟，路径里的箭头还是活的闭包；自由单子把操作本身也变成标签。与第四篇从闭包链到帧列表那一步平行。
- **handler 是代数，处理是 fold**：签名函子 F 描述操作，Free F 是没有解释的语法树，handler 是一个 F-代数；多种效应是 Free(F + G)，各个 handler 只认自己的标签。单孔对多孔，在运行一侧对应一次性的栈对可多次恢复的树。
- **Barr 与 Wells 14.2**：rec(A, B) ≅ A\* × B，局部递归与 locos；多项式函子在 locos 上有自由代数。Claude 7/13 有一个自己也说粗的读法：每个 tag 是一个基点，各自的栈建在各自的切片里。
- **延续单子不是自由单子**（8/28）；它是 codensity 一侧的构造。

**10/7 复核**。Noah 请 Claude 重新审一遍这条思路；结论是方向成立，上面有三处说法要收紧，另补一点。这是按定义推的，没有查文献。

- **两种列表不是同一个**：帧的列表是把复合留着不做，它表示的是树上每个节点里那条延续；操作的列表是单孔时树的脊。「树退化成列表，也就是栈」把两者混在了一起。上面「两次变成数据」那一条才是准确的说法：留着复合不做，和留着操作不解释，是两件独立的事。
- **「自由范畴是自由单子的退化情形」不够准**：准确的说法是，自由单子的 Kleisli 范畴是由各个操作生成的、带有限余积的自由范畴。自由范畴里只有路径；添上余积，路径可以按回答分情形，才分叉成树。所以 Noah 当年从 Kleisli 范畴加自由范畴去理解自由单子，差的是「带余积」这几个字，不是路走错了。
- **栈不是幂对象**：它带着 `apply-cont` 这个求值映射，但不同的列表可以表示同一个函数，唯一性不成立。「逆否帧喂不进值」的论证不受影响。
- **补充：为什么多个 tag 必须留着列表**。自由范畴里路径的分解是唯一的，复合以后就不唯一了，求值函子把「在哪里接的」忘掉了。在 tag 处切开栈靠的正是这份记忆。第三篇只有一条边界，那一刀由宿主的调用栈替我们记着；边界有了名字、不止一条，就只能自己记。

文献候选，都是当时对话里提到的，没有核：van der Ploeg 与 Kiselyov《Reflection without Remorse》（Kleisli 箭头的队列就是延续栈）；Forster 等 2017、Piróg 等 2019（深 handler 与 shift0/reset0 互相可表达）；Plotkin 与 Pretnar 的 handler；Swierstra《Data Types à la Carte》。

## 叙事思路：6/3 那次对话（10/8 补记）

第二部的叙事路线 Noah 在 6/3 讲过一遍：从 typed monoid 引出范畴，再靠逐步放开 hom 的参数得到函子、自然变换与米田。Noah 10/8 23:49：那时还没有决定把重写 CTP 当作第二部，但那次的叙事思路很有参考价值。出处：[6/3 技术文章的文献引用指南](https://claude.ai/chat/3aedb0e9-0a62-4b77-8188-00349bf2087e)，第 14、18 轮。

Noah 当时的原话：

> 实际上这一部写完，下一个系列我想用类似的风格写范畴论了。目前的出发点是从常用的例子，比如加法乘法，列表拼接作为例子抽象出 monoid，然后指出给元素加上类型，有些类型的元素可以复合，有些不能，得到 typed monoid ，也就是 category。元素加上类型就是态射了，只有首尾相连的才能复合。

> 其实屠龙我预想过很多遍，说说我的想法吧。首先是 typed monoid 引出范畴，然后就是像 ctp 一样将范畴抽象成 dom cod 等五个运算符。之后就是介绍 hom set，然后把 hom set 的一个对象替换成任意对象，得到 hom 函子，进而抽象出函子。再把另一个对象替换成态射，进而引出自然变换。而这些都是 Set-valued 的，引出米田也很方便？之后抽象出 Cat ，进一步得到 2-范畴，再回过头把 set 当作 0-范畴抽象得到 n 范畴。
>
> 而伴随，kan 扩展，极限等概念，我觉得是可以从预复合函子，或者说 hom 或者米田进一步抽象。

路线拆开看：

1. 加法、乘法、列表拼接，抽象出 monoid。
2. 给元素加上类型，只有首尾相连的才能复合：typed monoid 就是范畴。
3. 像 CTP 那样把范畴抽象成 dom、cod 等五个运算符。
4. hom 集；放开一个对象得到 hom 函子，进而抽象出函子。
5. 把另一个对象换成态射，引出自然变换；都是取值在 Set 里的，米田顺势出来。
6. 抽象出 Cat，得到 2-范畴；回头把 Set 看作 0-范畴，得到 n-范畴。
7. 伴随、Kan 扩展、极限，从预复合函子（或者说 hom、米田）再抽象。

Claude 当时的看法（不是决定）：

- 这条线的叙事引擎是「逐步放开 hom 的参数」，每一步都是把固定的东西变成自由的。
- 第 7 步要加固：读者还没见过极限与伴随的具体例子，就被告知它们是 Kan 扩展的特例。先各给一两个例子（积、自由幺半群），再说统一。
- Set 的特殊地位要早交代，在 hom 集之前。
- 同类工作的比较（Milewski、Seven Sketches、Riehl、Cheng）是凭记忆说的，没有核对。

与现在的计划怎么接，未定。Noah 10/8 定两部连着读、第一部负责构造动机（见「定位与发布」）。Claude 的推断：第一部已经造了好几个带复合的世界，第 1、2 步的开场可以直接拿它们当例子，而不必只靠加法与列表拼接；要不要这样做由 Noah 定。

## 单子由伴随给出：Noah 10/12 的草稿

Noah 10/12 提议第一部只从 Kleisli 复合讲单子，`anf:let*` 直接用 `∘𝒦` 定义，第二篇删去 `cps->neg²`；由伴随函子、η 与 μ 等自然变换定义单子的讲法留给第二部，作引子和素材。第一部那一侧的改动记在仓库 issue #56，这里只存第二部要用的部分。

Noah 的原话：

> 目前的单子定义叙事里，实际上是用到 Kleisli 范畴的那对伴随函子定义的，ε 实际上就是柯里化处理了下的 bind。目前第二篇叙事里对应的是 cps->neg²。而问题在于这个定义对读者来说可能很古怪，我在考虑要不要直接用复合来定义 let\* 语法，正好正文里也是要展开 let\* 语法，演示本质是 Kleisli 复合。以下代码讲自然变换，定义为将态射映射到自然条件的对角线，给出了 M η ε 的定义后，有：

```racket
(define-type (→𝒦 p q) (→𝒞 p (M q)))
```

Claude 10/12 按定义核对（推导，没有查文献）：

- `G` 与 `ε` 能是同一个函数，是因为 `(→𝒦 (M p) q)` 展开就是 `(→𝒞 (M p) (M q))`，两个签名说的是同一种箭头，只是一个按 𝒦 读、一个按 𝒞 读。照 Noah 的约定（自然变换作用在态射上，取自然方块的对角线），ε 作用在 f 上就是 bind f。
- `T = (∘ G F)` 把 f 送到 bind(η ∘ f)，就是函子 M 作用在 f 上；`μ = (∘ G ε F)` 是 μ 那个自然方块的对角线，即先 join 再作用 f。`S`、`δ` 是 𝒦 一侧的余单子，对称地成立。
- `let*𝒦` 里的类型标注用了没有绑定的 `a`、`b`，作示意没问题。`f1 = (∘𝒦 f0 id)` 按第一行 `∘𝒦` 的定义展开就是 `(G f0)`，所以 `let*𝒦` 等于 bind；这正是第一部想绕开、第二部要点破的那一步。
- Racket 8.10 实测：把这个宏放到第二篇的世界里（`M` 取 ¬¬，`id` 取 `(∘)`），第二篇的 `mul` 与 `(1 + 2) × 3` 都跑出正确结果。
