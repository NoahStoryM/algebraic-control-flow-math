# amb、Kanren 的调度与 Stream ∘ Maybe：Claude 的看法（2026-11-09）

请先回答 `审核说明-amb与Kanren调度-2026-11-09.md`，再读这一份。下面是 Claude 对各条的倾向，标注把握程度；都是推导，没有核过文献。

**A. 单子与它的运算**

- 1：倾向成立。两边是同一个多项式函子的不动点：`1 + a × X + X` 与 `1 + (1 + a) × X` 只差分配。要限定的是：thunk 每次调用都会重新计算，PAUSE 节点的尾部则会被记忆；这不影响答案与暂停的序列（E8 实测），但两者作为数据并不完全相同。
- 2：有限情形倾向成立：`List (1 + a)` 是 `1 + a` 上的自由幺半群，也就是「幺半群加一个常元」这个理论在 `a` 上的自由代数。无限的流上，`bind` 遇到无限的内层流时，后面的元素永远轮不到，所以要说清在什么意义下（余归纳、生产性）仍是单子。这一点 Claude 没有把握。
- 3：倾向成立，但说不出最强的版本。直觉上，在有限情形下，答案的多重集合是一致的；顺序依赖括号方式。是否有一个合适的商（例如按答案的多重集合）使 `append-inf` 结合、`append-map-inf` 满足单子律，请 Astra 判断。
- 4、5：较有把握。`tick >>= k = tick` 正对应 `amb-empty` 不调用 continuation。
- 6：有限流上较有把握。「失去生产性」这个说法是 Claude 对 E7 的解释，可能有更标准的术语。
- 7：**Claude 认为很可能不成立，说过头了。** ambKanren 现状（11/8 之前的 `suspend`）用了第四种做法：把 `tick` 解释成「在 amb 自己的全局前沿里把剩余计算挪到后面」。它既不把 Pause 留在值里，也不商掉，而是给 `tick` 一个调度上的解释。E2 中现状 13 个程序全同、没有饿死，靠的就是这个；代价是书中例子有 15 项顺序不同。所以准确的说法大概是：在「保持原书顺序」的前提下才只有这三种，而这个前提本身需要定义清楚。

**B. reify、reflect 与融合**

- 8：倾向「同一个形状，不是同一回事」。Filinski 的 reflect / reify 是用 `shift` / `reset` 对任意可定义的单子统一给出的；这里是对 `T` 手写的特例，暂停又借了 amb 的选择点。两者的关系值得 Astra 说准。
- 9：解释是 Claude 的，只有 E4 的计时支持，没有证明。
- 10：倾向成立。可能的限定：叶子目标也可以直接给出成熟的流，完全不经过 amb；那样 amb 只剩手写的直接风格目标在用（E7 的版本就这样处理了 `==`、`succeed`、`fail` 的流形式，但 `==` 仍在 amb 里合一）。

**C. 效应与 handler 的嵌套**

- 11、12：较有把握，与 7 月以来第七章的「两个 tag 两种嵌套」草稿（`two-tags-nesting-20261015.rkt`）应当是同一个现象，只是把「选择加状态」换成了「选择加中止」。
- 13：较有把握，E6 有反例与修复的实测。
- 14：前半倾向成立，后半不确定。`Maybe` 与 `Stream` 之间有分配律，应当不在 No-Go 结果禁止的范围内；但 Claude 没有读过那篇文章，不能确认。

**D. Kanren 的两个版本**

- 15：较有把握，E1 与 ambKanren TRS1 的 228 项测试支持。
- 16：较有把握，E2 的那个饿死例子是直接证据。
