# 关系的世界

`inclusive-range` 收到一组边界，交出其间所有的数；`right-triangles` 收到一组边界，交出所有的直角三角形。两个都是交出列表的函数，表示的都是关系。

`inclusive-range` 表示的关系，`between` 也表示：把 `between` 放进 `in-amb`，交出的正是 `inclusive-range` 的那张列表。

```racket
(inclusive-range l h) = (in-amb (between l h))
```

区别在写法。`between` 写出来是个普通的函数，收到两个数，交出一个数；同一组输入在表里占几行，它就返回几次。没有 amb 的时候，函数只能表示每个输入恰好占一行的关系；有了 amb，普通写法的函数可以表示任何二元关系。

`right-triangles` 也可以这样得到。挑边的每一步都写成这样的函数，一步收到一项，交出一项，把后面用得着的数带上；四步用普通的 `∘` 接起来，再放进 `in-amb`：

```racket
(define pick-a (match-λ [(list l   h) (list (between l h)   h)]))
(define pick-b (match-λ [(list a   h) (list a (between a h) h)]))
(define pick-c (match-λ [(list a b h) (list a b (between b h))]))
(define (check-right t) (check (apply pyth? t)) t)

(define right-triangle (∘ check-right pick-c pick-b pick-a))
(define (right-triangles l h) (in-amb (right-triangle (list l h))))

(right-triangles 1 20)
;; =>
'((3 4 5) (5 12 13) (6 8 10) (8 15 17) (9 12 15) (12 16 20))
```

每一步都是一个关系，接起来的 `right-triangle` 还是一个关系，它的表里是全部的行。两步接起来，`(l h)` 与 `(a b h)` 相关，是因为存在一个中间的 `(a h)`，让前后两步同时成立。数学里这叫关系的**复合**（composition）：

```latex
Q \circ P = \{\, (x, z) \mid \exists y,\ (x, y) \in P \,\land\, (y, z) \in Q \,\}
```

`pick-a` 交出一项，`pick-b` 接着用；「存在中间项」由 amb 兑现，每个中间项都会走到。这样的函数是输入与输出之间的二元关系（binary relation），把带 amb 的宿主记作 ℬ。在 ℬ 里，函数就是关系，函数的复合就是关系的复合。

可是 amb 不是宿主原有的运算，`between` 也不是纯函数，它们是靠 `shift` 和 `reset` 做出来的。第二篇遇到过同样的处境：纯的宿主 𝒟 里没有 `call/cc`，带 `call/cc` 的宿主是 𝒞。那里的办法是在 𝒟 里另造一个世界 𝒦 来模拟 𝒞，把箭头的类型从 `p → q` 改成 `p → ¬¬q`，再给它配上自己的复合。这里照样做一遍。

要造的世界其实早就有了，就是交出列表的函数：箭头的类型改成 `p → (Listof q)`，一个输入对应的结果一次全交出来。把它记作 ℒ，取自列表（list）。这样的箭头是纯函数，`inclusive-range` 就是 ℒ 里的 `between`。

```racket
(define-type (→ℒ p q) (→ p (Listof q)))
```

ℒ 的箭头不能用 `∘` 接：前一个交出一张列表，后一个只收其中一项。该怎么接，可以从 ℬ 那边问出来。把 ℬ 里两步的复合放进 `in-amb`，看它交出什么：

```racket
(in-amb (g (f x)))
= (append-map (λ (y) (in-amb (g y))) (in-amb (f x)))
```

对前一步交出的每一项，收集后一步的结果，再接成一张。这就是 ℒ 里的复合，记作 `∘ℒ`：从最右边的一步起，逐个用 `append-map` 接上。

```racket
(: ∘ℒ (∀ (p ...) (→ (→ℒ pn-1 pn) ... (→ℒ p1 p2) (→ℒ p1 pn))))
(define ((∘ℒ . f*) x) (foldr append-map (list x) f*))
```

两个世界之间，箭头可以来回搬。从 ℒ 到 ℬ，把交出的列表交给 amb 去选；从 ℬ 到 ℒ，用 `in-amb` 把结果收回来：

```racket
(: list->amb (∀ (p) (→ (Listof p) p)))
(define (list->amb v*) (for/amb ([v (in-list v*)]) v))

(define ((ℒ->ℬ f) . x*) (list->amb (apply f x*)))
(define ((ℬ->ℒ g) . x*) (in-amb (apply g x*)))
```

`list->amb` 与擦掉延续参数时得到的 `choose` 是同一个函数，这里用 `for/amb` 把它重写了一遍。开头的那条等式说的就是 `(ℬ->ℒ between)` 是 `inclusive-range`；反过来，`(ℒ->ℬ inclusive-range)` 是 `between`。搬过去再搬回来，得到的还是原来的箭头。`right-triangles` 是先复合再搬；先搬再复合，结果也一样：

```racket
((∘ℒ (ℬ->ℒ check-right) (ℬ->ℒ pick-c) (ℬ->ℒ pick-b) (ℬ->ℒ pick-a)) '(1 20))
;; =>
'((3 4 5) (5 12 13) (6 8 10) (8 15 17) (9 12 15) (12 16 20))
```

所以 ℬ 与 ℒ 同构，是同一个世界的两种写法。

第二篇最后用 `anf:let*` 把 𝒦 里的程序写回了绑定的样子。ℒ 也有这样的写法，而且是现成的：`for*/list`。遍历搜索的那三层循环是 ℒ 里的程序，`in-amb` 里的那段 `let*` 是 ℬ 里的同一个程序，一行对一行：`[a (inclusive-range l h)]` 对 `[a (between l h)]`，`#:when (pyth? a b c)` 对 `(check (pyth? a b c))`。这一篇正是沿着这条路走过来的：从 ℒ 的循环出发，把藏着的延续写成参数，再用 `shift` 擦掉它，就到了 ℬ。

| 纯的宿主 𝒟 加上 | 得到的世界 | 在 𝒟 里模拟它的世界 | 箭头的类型 | 复合 |
| --- | --- | --- | --- | --- |
| `call/cc` | 𝒞 | 𝒦 | `p → ¬¬q` | `∘𝒦` |
| amb | ℬ | ℒ | `p → (Listof q)` | `∘ℒ` |

列表记着结果的先后和重复，表不记这些。把两个世界的箭头都看作关系时，先后与重复不计。
