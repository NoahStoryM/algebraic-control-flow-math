# 关系的世界

amb 不是宿主原有的运算，`between` 也不是纯函数，它们是靠 `shift` 和 `reset` 做出来的。第二篇遇到过同样的处境：纯的宿主 𝒟 里没有 `call/cc`，带 `call/cc` 的宿主是 𝒞。那里的办法是在 𝒟 里另造一个世界 𝒦 来模拟 𝒞，把箭头的类型从 `p → q` 改成 `p → ¬¬q`，再给它配上自己的复合。这里照样做一遍。

带 amb 的宿主记作 ℬ，在 ℬ 里，函数就是二元关系，函数的复合就是二元关系的复合。要造的是在 𝒟 里模拟 ℬ 的世界。

这个世界其实早就有了，就是交出列表的函数：箭头的类型改成 `p → (Listof q)`，一个输入对应的结果一次全交出来。把它记作 ℒ，取自列表（list）。这样的箭头是纯函数，`inclusive-range` 就是 ℒ 里的 `between`。两个世界的箭头类型各起一个名字：

```racket
(define-type (→ℬ p q) (→ p q))
(define-type (→ℒ p q) (→ p (Listof q)))
```

箭头可以在两个世界之间搬。从 ℒ 到 ℬ，把交出的列表交给 amb，散成几条时间线，叫 `scatter`；从 ℬ 到 ℒ，用 `in-amb` 把各条时间线的结果收成一张列表，叫 `gather`：

```racket
(: list->amb (∀ (p) (→ (Listof p) p)))
(define (list->amb v*) (for/amb ([v (in-list v*)]) v))

(: scatter (∀ (p q) (→ (→ℒ p q) (→ℬ p q))))
(define (scatter f) (∘ list->amb f))

(: gather (∀ (p q) (→ (→ℬ p q) (→ℒ p q))))
(define ((gather g) . x*) (in-amb (apply g x*)))
```

`list->amb` 与擦掉延续参数时得到的 `choose` 是同一个函数，这里用 `for/amb` 把它重写了一遍。`(scatter inclusive-range)` 是 `between`，`(gather between)` 是 `inclusive-range`。搬过去再搬回来，得到的还是原来的箭头：`(in-amb (list->amb v*))` 把 `v*` 的每一项各包成一张列表，再接起来，还是 `v*`；反过来，`(list->amb (in-amb e))` 把 `e` 的结果收齐了再逐个交出，后面的计算看到的还是那些结果。

ℒ 的箭头不能用 `∘` 接：前一个交出一张列表，后一个只收其中一项。ℬ 的箭头却能接。那就把 ℒ 的箭头搬到 ℬ，在那边用 `∘` 接好，再搬回来；第二篇的 `∘𝒦` 也是这样绕道另一个世界得来的。ℒ 的复合记作 `∘ℒ`，它应当是：

```racket
(∘ℒ g f)  =  (gather (∘ (scatter g) (scatter f)))
```

这条路绕过了 ℬ，用到了 amb，而 ℒ 要住在纯的宿主里。把它用在 `x` 上，展开 `gather` 与 `scatter`，再化简：

```racket
((∘ℒ g f) x)
= (in-amb (list->amb (g (list->amb (f x)))))
= (append-map (λ (y) (in-amb (list->amb (g y)))) (f x))
= (append-map g (f x))
```

第二行里先求值的是里面的 `list->amb`：剩下的计算为 `(f x)` 的每一项 `y` 各走一遍，各自收成列表，再接起来，这就是第三行。其中 `(in-amb (list->amb (g y)))` 是搬过去又搬回来，就是 `(g y)`。amb 不见了，剩下的是纯函数：对前一步交出的每一项调用后一步，把结果接成一张。多于两步时，从最右边的一步起，逐个用 `append-map` 接上：

```racket
(: ∘ℒ (∀ (p ...) (→ (→ℒ pn-1 pn) ... (→ℒ p1 p2) (→ℒ p1 pn))))
(define ((∘ℒ . f*) x) (foldr append-map (list x) f*))
```

`(gather right-triangle)` 是先复合再搬，交出的就是 `right-triangles` 的那张列表。先搬再复合，结果也一样：

```racket
((∘ℒ (gather check-right) (gather pick-c) (gather pick-b) (gather pick-a)) '(1 20))
;; =>
'((3 4 5) (5 12 13) (6 8 10) (8 15 17) (9 12 15) (12 16 20))
```

所以 ℬ 与 ℒ 同构，是同一个世界的两种写法。

第二篇最后用 `anf:let*` 把 𝒦 里的程序写回了绑定的样子。ℒ 也有这样的写法，而且是现成的：`for*/list`。遍历搜索的那三层循环是 ℒ 里的程序，`in-amb` 里的那段 `let*` 是 ℬ 里的同一个程序，一行对一行：`[a (inclusive-range l h)]` 对 `[a (between l h)]`，`#:when (pyth? a b c)` 对 `(check (pyth? a b c))`。这一篇正是沿着这条路走过来的：从 ℒ 的循环出发，把藏着的延续写成参数，再用 `shift` 擦掉它，就到了 ℬ。

| 纯的宿主 𝒟 加上 | 得到的世界 | 在 𝒟 里模拟它的世界 | 箭头的类型 | 复合 |
| --- | --- | --- | --- | --- |
| `call/cc` | 𝒞 | 𝒦 | `p → ¬¬q` | `∘𝒦` |
| amb | ℬ | ℒ | `p → (Listof q)` | `∘ℒ` |

列表记着结果的先后和重复，表不记这些。把两个世界的箭头都看作关系时，先后与重复不计。
