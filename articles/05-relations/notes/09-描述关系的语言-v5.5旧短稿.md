# 描述关系的语言

谓词是函数，只能按键查表：给它一组数，它回答是或否。我们想要的却是反过来，找出所有值为 `#t` 的行。函数做不到，只能由我们把笛卡尔积里的元素一组组列出来去问；第一节的三层循环做的就是这件事，为了六组边试了 1540 组。能不能只写下条件，让语言去把行找出来？

设想有一门语言，可以直接写关系。谓词 `pyth?` 和 `<=` 在其中各有对应的关系，记作 `pythᵒ` 和 `≤ᵒ`，写法和谓词一样，只是参数可以是还不知道的数。上一节的 R，给定边界 l 和 h 以后，剩下的是三条边要满足的条件：

```latex
\{\, (a, b, c) \in \mathbb{N}^+ \times \mathbb{N}^+ \times \mathbb{N}^+ \mid (l \le a \le b \le c \le h) \,\land\, (a^2 + b^2 = c^2) \,\}
```

用这门语言照着写下来：

```racket
(define (right-triangles l h)
  (run* (a b c)
    (≤ᵒ l a b c h)      ; l ≤ a ≤ b ≤ c ≤ h
    (pythᵒ a b c)))     ; a² + b² = c²

(right-triangles 1 20)
;; =>
'((3 4 5) (5 12 13) (6 8 10) (8 15 17) (9 12 15) (12 16 20))
```

`run*` 对应集合的花括号：`(a b c)` 是竖线左边的形状，后面两行是竖线右边的条件。两行里的 a、b、c 是同一组还不知道的数，两个条件要由它们同时满足。`run*` 找出所有这样的行，收进列表交出，正是第一节那个函数交出的列表。

循环不见了，找出这些行的事交给了语言。这还只是伪代码，上面的结果是后面把它实现以后跑出来的。参数可以未知，也不等于随便哪个参数留空都能解：这次查询给定的是边界，要找的是三条边。那么，程序里只写了条件，答案里的数究竟从哪里来？
