# 关系的世界

`amb` 不是宿主原有的运算，`between` 也不是纯函数，它们是靠 `shift` 和 `reset` 做出来的。第二篇遇到过同样的处境：纯的宿主 𝒟 里没有 `call/cc`，带 `call/cc` 的宿主是 𝒞。那里的办法是在 𝒟 里另造一个世界 𝒦 来模拟 𝒞，把箭头的类型从 `p → q` 改成 `p → ¬¬q`，再给它配上自己的复合。这里照样做一遍。

带 `amb` 的宿主记作 ℬ，在 ℬ 里，函数就是二元关系，函数的复合就是二元关系的复合。要造的是在 𝒟 里模拟 ℬ 的世界。

𝒟 是 ℬ 的一部分：纯函数是每个输入恰好占一行的二元关系，放进 ℬ 里同样合法。ℬ 的箭头还是普通的函数类型，复合就是普通的 `∘`：

```racket
(define-type (→𝒟 p q) (→ p q))
(define-type (→ℬ p q) (→ p q))

(: inj (∀ (p q) (→ (→𝒟 p q) (→ℬ p q))))
(define (inj f) f)

(: ∘ℬ (∀ (p ...) (→ (→ℬ pn-1 pn) ... (→ℬ p1 p2) (→ℬ p1 pn))))
(define ∘ℬ ∘)
```

要造的世界其实早就有了，就是交出列表的函数：箭头的类型改成 `p → (Listof q)`，一个输入对应的结果一次全交出来。把它记作 ℒ，取自列表（list）。这样的箭头是纯函数，`inclusive-range` 就是 ℒ 里的 `between`。

```racket
(define-type (→ℒ p q) (→ p (Listof q)))
```

ℬ 与 ℒ 表示的是同一样东西，二元关系，所以箭头可以在两个世界之间搬。从 ℒ 到 ℬ，把交出的列表交给 `amb`，散成几条时间线，叫 `scatter`；从 ℬ 到 ℒ，用 `in-amb` 把各条时间线的结果收成一张列表，叫 `gather`：

```racket
(: list->amb (∀ (p) (→ (Listof p) p)))
(define (list->amb v*) (for/amb ([v (in-list v*)]) v))

(: scatter (∀ (p q) (→ (→ℒ p q) (→ℬ p q))))
(define (scatter f) (∘ list->amb f))

(: gather (∀ (p q) (→ (→ℬ p q) (→ℒ p q))))
(define ((gather g) . x*) (in-amb (apply g x*)))
```

`list->amb` 与擦掉延续参数时得到的 `choose` 是同一个函数，这里用 `for/amb` 把它重写了一遍。`(scatter inclusive-range)` 是 `between`，`(gather between)` 是 `inclusive-range`。搬过去再搬回来，得到的还是原来的箭头：`(in-amb (list->amb v*))` 把 `v*` 的每一项各包成一张列表，再接起来，还是 `v*`；反过来，`(list->amb (in-amb e))` 把 `e` 的结果收齐了再逐个交出，后面的计算看到的还是那些结果。

ℒ 的箭头不能用 `∘` 接：前一个交出一张列表，后一个只收其中一项。ℬ 的箭头却能接。那就把 ℒ 的箭头搬到 ℬ，在那边接好，再搬回来；第二篇的 `∘𝒦` 也是这样绕道另一个世界得来的。

```racket
(: ∘ℒ (∀ (p ...) (→ (→ℒ pn-1 pn) ... (→ℒ p1 p2) (→ℒ p1 pn))))
(define (∘ℒ . f*) (gather (apply ∘ℬ (map scatter f*))))
```

这个定义绕过了 ℬ，用到了 `amb`，而 ℒ 要住在纯的宿主里。拿两步的情形，展开 `gather` 与 `scatter`，再化简：

```racket
  ((∘ℒ g f) x)
= ((gather (∘ℬ (scatter g) (scatter f))) x)
= ((gather (∘ list->amb g list->amb f)) x)
= (in-amb
   (let* ([y (list->amb (f x))]
          [z (list->amb (g y))])
     z))
= (reset
   (let* ([y (choose (f x))]
          [z (choose (g y))])
     (list z)))
= ((choose/k (f x)) (λ (y) ((choose/k (g y)) list)))
= (for*/list ([y (f x)]
              [z (g y)])
    z)
= (append-map (λ (y) (append-map list (g y))) (f x))
= (append-map (λ (y) (g y)) (f x))
= (append-map g (f x))
```

展开之后原路往回走，依次是这一篇出现过的四种写法：`in-amb` 里的 `let*`，`reset` 里的 `choose`，交给 `choose/k` 的延续，`for*/list` 的循环。循环摊开就是 `append-map`；`(append-map list v*)` 把每一项各包成一张列表再接起来，还是 `v*`，里面那一层就化掉了。`amb` 不见了，剩下的是纯函数：对前一步交出的每一项调用后一步，把结果接成一张。多于两步时也一样，从最右边的一步起，逐个用 `append-map` 接上。于是 `∘ℒ` 可以不经过 ℬ，直接在 𝒟 里定义：

```racket
(define ((∘ℒ . f*) x) (foldr append-map (list x) f*))
```

ℬ 与 ℒ 模拟的都是二元关系，`gather` 与 `scatter` 互相抵消，复合也对得上。所以 ℬ 与 ℒ 同构，是同一个世界的两种写法。

列表记着结果的先后和重复，表不记这些。把两个世界的箭头都看作关系时，先后与重复不计。
