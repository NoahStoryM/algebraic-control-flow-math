### §8 让关系语言跑起来

**带走（v5.4）**
1. 列表世界里方向是定死的：输入用模式拆开，输出用构造拼上。关系没有方向，两头都得能写成带未知项的模式；两头都可以有未知项的匹配，就是合一。
2. 未知项要能在几个目标之间共享，所以它自己是一个值，目前知道了什么另外记在代换里。
3. amb 管回溯，合一管未知项。两样合起来，§3、§4 的两版程序原样运行，`swapo` 两个方向都能跑。这是 miniKanren 的一个精简版。

**内容**
- 入口（v5.4）：回看 §5 的 `pick-bo`（`match-define` 拆、`list` 拼）与 §4 的 `pick-bo`（两个 `==`，两头都是模式）。单向的匹配里，模式的另一边是已经确定的值；合一是它的双向版本。
- `independent` 的例子（110 个答案，出现 `(4 3 5)`）留着，回答「未知项为什么不能各选各的、为什么要有代换」。它与入口谁先谁后，写的时候定。
- `(run* (x y) (== x y) (== y 3))` 交出 `((3 3))`；`var`、代换、`walk`、`unify`（含 occurs 检查）、`walk*`；「每条分支带着自己的代换往下走；一条分支失败，不会改动其他分支手里的代换」；`conj` 与 ∧：「前一个目标交出满足自身条件的代换，后一个在这些代换上继续求解；最后留下的答案，就同时满足两个条件」；`betweeno`、`pytho` 要求参数已确定，所以目标的顺序有关系（可加一句：数据库交给查询优化器，这门语言按写出的顺序深度优先地找）；对应表（`(conj)` 是 ⊤，`(disj)` 是 ⊥，`fail` 不是目标不进表）；`swapo`；末尾点名 miniKanren。正文展示的答案都已确定，不重整未确定的变量。

**准确性（v5.4）**
- 合一不参与遍历。遍历是回溯的事；合一让条件可以不分方向地写。不写「用合一和回溯实现遍历」。
- 只能说「miniKanren 的一个精简版」：`betweeno`、`pytho` 只认确定的数，取前 n 个答案在无穷的关系上停不下来。
- 「合一是双向的模式匹配」是口号；准确的说法是：模式匹配是其中一边没有未知项的合一。

**内核代码**：写法待定（Noah 10/3：等前面的叙事定下来再设计）。初稿用的是 `choose` / `fail` / `collect`；另一种是照 ambKanren 的 `demo.rkt` 用 `amb`、`for/amb`、`in-amb`。两种都已有通过测试的代码（§8 子模块、`notes/kanren-check/`）。

**代码**：§8 全部（子模块 `relational`）。

## 五、创作者笔记（不进正文，除非某一节真的用得上）

**表的更多读法**
- 函数是键唯一的表；谓词相当于给「所有可能的行」添一列布尔值，标着 `#t` 的那部分就是关系；存容器的函数摊开就是关系的表。关系的两种表示（谓词、交出列表的函数）都可以读成函数的表。不对称：由交出列表的函数得到谓词只要一次 `member`，反过来还缺候选从哪里来。
- n 列的表是 n 元关系；「几元只是看成几组」（Rel compact closed，Rel(X, Y) ≅ Rel(1, X × Y)）。填列就是部分应用：`(λ (c) (pyth? 3 4 c))` 是一元关系，`(λ () (pyth? 3 4 5))` 是零元关系，零元谓词即 `(→ Boolean)`，纯的只有两种，正是两个布尔值。若用，候选位置是 §8 讲空合取、空析取处；只在数学层面说（列表层面 `(run* () …)` 可交出 `'(() ())`）。
- 结果树：嵌套的 `for/list` 保留分支层次（已执行 `#:when`，不是搜索过程的记录）；压平即 `append-map`。1 到 20：8000 个组合 → 1540 个候选 → 六个答案。
- 顺序：列表里行的先后是叶子被走到的先后；这棵树叶子同层，深度优先与逐层展开交出的顺序相同，只是干活的顺序不同（`∘ℒ` 逐层，`choose` 深度优先）；叶子深度不齐或分支无穷时才不同。

**关系代数与关系演算**
- 同一张表有两种谈法：代数（整张表的运算：筛选、投影、连接、并、差）与演算（写出一行要满足的条件：∧、∃、=）。Codd 证明两者在基本范围内表达力相同。SQL 写出来像演算，执行时转成代数。逻辑式编程在演算这一边；Datalog 是过渡。
- 本篇两种都有：§3、§4 的假想语言是演算的写法；§5 的 `∘ℒ` 是代数的写法（复合 = 在中间那组列上连接，再投影掉）；§7 的 `choose` 回到一行一行地找。
- 对照：并列的目标共享未知项 ↔ 连接；`fresh` 引入而不交出的项 ↔ 投影掉的列；`==`、`pytho` ↔ 筛选；`disj` ↔ 并；`run*` 的未知项 ↔ 最后的投影。
- 类比断开处：数据库的表有限、存下来，这里的关系由条件定义、现场计算、可以无穷；SQL 默认不去重、不保证顺序；数据库有优化器，这门语言按序深度优先；逻辑变量可绑定到部分结构（合一）；递归；否定（差）本篇不碰。
- 正文不用「关系代数」「关系演算」这两个词。

**「构造一张表」与构造逻辑（Noah 10/3 问起）**
- 对应的不是构造逻辑。构造逻辑对上的是函数式那一支：命题是类型，证明是程序，运行是化简证明。关系语言是另一支：程序是一组公式，查询是带存在量词的公式，运行是找证明，答案是证明里给出的见证。
- 接点只有「说存在就得拿出见证」：`run*` 交出的每一行都是一个见证。这门语言只用到 =、∧、∨、∃、⊤、⊥（§8 的对应表正好是这几行），没有否定和全称；在这一小块里，经典逻辑与构造逻辑能证出的东西相同，所以「构造」二字在这里区分不出什么。正文不提。
- 「构造一张表」更实在的读法是由小表造大表，见上一条「关系代数与关系演算」里的对照。v5.4 把其中复合的那一句放进 §4。

**范畴论侧**（详见 `archive/art5-plan.v4.9.md` 与 `art6-plan.md` 第七节）
- 四个范畴：Host、Host_amb、Rel、Kl(List)。Kl(List) → Rel 取支撑，保持复合，不忠实；`Host_amb ≃ Kl(List)` 只在受限意义下成立（有限终止、无其他效应、延续可多次调用、按 `collect` 的列表观察、一阶数据）。与第二篇只能说「都在直接风格与显式编码之间往返」，不说三个世界同形，Rel 不对应 𝒰。
- 两种表示之间的往返（Noah 10/2）：`f : a → (Listof b)` 与用 `choose` 写的 `g : a → b` 互相得到，`g = (λ (a) (choose (f a)))`，`f = (λ (a) (collect (λ () (g a))))`；用 amb 库的写法就是 `for/amb` 与 `in-amb`，看上去是两种容器之间的转换。这一对就是 reflect / reify（Astra 第一轮写作 `reflect-arrow` / `reify-arrow`）。列表 → `choose` → 列表逐字还原（顺序与重数都在）；`choose` → 列表 → `choose` 在上面的受限意义下不可区分；两个方向都保持单位与复合（收回两段的普通 `∘`，等于各自收回以后的 `∘ℒ`）。代码见「附-d」。与第二篇的对应：`choose : (Listof a) → a` 与 `call/cc : ¬¬a → a` 同形，都把显式编码里的值放回直接风格（`uncps` 用的就是 `call/cc`）；`collect` 与 `cps` 同向，把直接风格的计算收成编码。区别：amb 的「容器」不是一个值，只有站在 `collect` 的边界上才看得见它的全部元素；边界之内的程序始终身处其中一个元素。正文不点破，留给第六篇（reflect / reify）。
- Rel 是 quantaloid；列表侧 `disj` 是有序追加；列表复合只对一侧分配；`conj` 按解集是 ∧（取交的是解集，不是代换上的关系）。
- 交错合取只在忽略顺序时满足结合律（有限纯情形）。
- 状态与非确定性：这个实现把代换状态与非确定性搜索接在一起；不说「逻辑式编程是状态与非确定性的组合」。

**amb 在第五篇里放多少（10/2 晚，Noah 问起；Claude 的看法，未定）**
- 第五篇的 `choose` / `fail` / `collect` 已经是一个最小的 amb：再加三行语法（`amb`、`for/amb`、`in-amb`）就能逐字跑出 amb 库文档里所有有限、深度优先的例子。它做不到的恰好是三件事：只要第一组、无穷的备选、换搜索的走法，也就是本篇「未解的线索」。
- amb 库 v2 与它的差别可以压成一句：`choose` 不再自己调用 `k`。第五篇是 `(shift k (append-map k p*))`，等待的工作留在宿主栈上；库是 `(shift-at tag k (amb-tree k …))`，把 `k` 交到边界，由边界上的循环拿着一张待办（frontier，第四篇的「前沿」）决定先走哪个，答案以惰性的流交出。压到最小约二十行，结果与库相同（取第一组直角三角形都是试到第 420 组候选就停；广度优先的顺序相同）。库的其余复杂度是工程上的：公平、多值、shuffler、向量压缩、不定长 `for/amb` 的协程写法（另用了一个 prompt tag）。
- control-context 文档里 call/cc 的 amb 没有 `in-amb`，因为没有边界：它天然是「找到第一个答案就往下走，想要下一个再 `(amb)`」。要补 `in-amb`，得用逃逸延续手搭一个边界，答案靠可变状态记下。三者正好互补：call/cc 版天然只要第一组，收齐要手搭边界；第五篇的 `choose` 天然收齐，只要第一组做不到；库 v2 有边界、有显式的待办、有惰性的流，两样都行。
- 文档那一版另有一个限制：备选本身又是 amb 时会丢答案，`(amb 1 (amb 2 3) (amb 4 5 6) 7 8)` 只得到 1 2 3 7 8（内层 amb 在外层生成器的 `get` 里求值，捕获的延续带着 `(set! s (stream-rest s))`，重入几次流就多前进几格）。
- 三份草图与检查在 `notes/amb-sketches.rkt`（27 项通过）。
- 结论（v5.2）：正文在「擦除延续参数」末尾用一个小节认出 amb（见第二节）；惰性的 `in-amb` 与可换的搜索策略不在本篇展开，它是「怎样退出整个搜索」的一个回答，形状上是「操作把 `k` 交给边界上的处理者」，留给讲多 prompt-tag 与代数效应的那一篇作例子。第六篇可以直接说「列表单子模拟的效应就是 amb」。

- **实验**（`notes/kanren-check/`）：把 `demo.rkt` 里的 typed/amb 换成第五篇的三个定义加三行语法，其余一字不动，去跑它自己选的那六章 TRS 测试（取自 miniKanren-typed，共 171 条）：141 条通过，0 条结果不符，30 条停不下来。停不下来的全是对有无穷多个答案的关系取前 n 个（`run 1`、`run 5` …），正是第九节的问题。换成二十来行的惰性版（`choose` 把 `k` 交到边界），171 条全部通过。结论：第五篇的 `choose`/`fail`/`collect` 足以撑起一个真的 miniKanren 内核的全部有限查询；缺的只是惰性的 `in-amb`。
- **miniKanren-typed**（TRS 第一版的实现加类型，`Goal = Substitution → (Streamof Substitution)`，`bind`/`mplus` 与交错版 `bindi`/`mplusi`）是同一门语言在「列表世界」里的写法：`bind` 就是流上的 `append-map`，`mplus` 是流的拼接。它与 ambKanren 的关系，正是第五节的 `pick-ao` 与第七节的 `pick-a` 的关系：改用 `choose` 以后，`bind` 变成普通的函数应用，`mplus` 藏进了 `choose`。交错（`condi`、`current-amb-fair?`）对应公平性，本篇不碰。若要在正文点一句，位置是第八节 `conj` 那一段（「熟悉 miniKanren 实现的读者会注意到这里没有 `bind` 和 `mplus`」）。
- **amb**（frontier 是不可变的双端队列，默认深度优先、不公平）与 **control-context**（`call/cc` 版 amb 用可变的 frontier；对照若要，放附录）：见上面「amb 在第五篇里放多少」。
