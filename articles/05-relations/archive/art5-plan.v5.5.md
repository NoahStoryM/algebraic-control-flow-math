### 15:03 之后 Claude 的回答（数学背景，归第八篇素材；正文不用这些词）

- 关系范畴确实是 2-范畴，但并不是纵向复合。Rel(A, B) = 𝒫(A × B) 按包含是偏序集，2-胞腔是 R ⊆ S，纵向复合是 ⊆ 的传递，横向复合是 ∘ 对 ⊆ 单调。并是每个 hom 偏序集里的上确界（余积），空关系是底。
- 复合对任意并两侧分配，所以 Rel 是 quantaloid（hom 是完备上半格的丰富范畴）。只看一个对象（代换到代换），目标构成 quantale，也就是幂等半环：`disj` 是加法，`conj` 是乘法，`fail` 是 0，`succeed` 是 1。
- 并可以从范畴自身得到：Rel 有双积，R ∪ S = ∇ ∘ (R ⊕ S) ∘ Δ，复制输入、各走各的、合并输出，正是 amb / `mplus` 的形状。
- 表的意象要分三种运算：复合是按中间那组列对齐、再去掉中间列（接）；并是同一形状的表上下叠（叠）；单纯左右并排是第三种，关系的积（miniKanren 的目标都作用在同一个代换上，用不到）。
- 单子一侧：𝒫 给出并（交换、幂等）；列表给出 `append`（不交换、不幂等），顺序与重复、`mplus` 与 `mplusi` 的差别都从这里来。左分配律 `(conj (disj g1 g2) h) = (disj (conj g1 h) (conj g2 h))` 在列表层面逐字成立，它就是 `choose = (shift k (append-map k p*))` 本身：把剩余工作分给每个备选（代数效应里「运算是代数的」）。右分配律只在集合意义下成立。已运行：`notes/conj-disj-distrib.rkt`。
- 合取的两种读法（接 13:43 Astra 的两层）：在解集层面，与、或是同一个格里的交与并；在代换的关系层面，或仍是并，与变成了复合。桥：只做过滤的关系（恒等关系的子集）复合起来就是取交。

### 15:18 之后 Claude 的回答（数学背景，归第八篇素材）

- 他的回忆都对：Rel(a, b) 是偏序范畴，对象是 a × b 的子集，态射是包含；并是余积，交是积。只取一个对象，单对象的 2-范畴就是（严格、不对称的）monoidal category：对象是目标，态射是包含，⊗ 是关系的复合，单位对象是恒等关系。一处措辞：纵向拼接是 **1-胞腔**的余积（hom 范畴里对象的余积），不是 2-胞腔的。
- 两个运算之间的性质：⊗ 在两个变量上都保持余积（而且是任意多个），即 distributive monoidal category（rig category 的特例）；因为是偏序且有任意并，它就是 quantale（SupLat 里的幺半群，单对象的 quantaloid）；保持任意并所以有右伴随，双侧闭，内部 hom 叫剩余 R\T、T/R；对交不保持，只有 (R ∩ S) ∘ T ⊆ (R ∘ T) ∩ (S ∘ T)；完备格上有不动点，递归关系的语义是最小不动点，R* = ⋃ Rⁿ。
- 名字与文献：幂等半环（dioid）；Kleene algebra 与带测试的 KAT（Kozen），测试是恒等关系的子集，即「只做过滤的关系」；quantale（Mulvey；Rosenthal）与 quantaloid；Tarski 的 relation algebra；allegory（Freyd & Scedrov；Bird & de Moor, Algebra of Programming）；逻辑式编程方面 Gallego Arias & Lipton, Logic Programming in Tabular Allegories（ICLP 2012）；单子一侧 Rivas, Jaskelioff, Schrijvers, From Monoids to Near-Semirings: the Essence of MonadPlus and Alternative（PPDP 2015），near-semiring 只要求一侧的分配律与零，与 `notes/conj-disj-distrib.rkt` 跑出来的现象一致。
- 核对情况：nLab 的 quantale、distributive monoidal category 两条与 ICLP 2012 那篇的题目、作者、摘要打开核对过；PPDP 2015 只核对到题目与作者；其余凭记忆，进文献表前要核对。

### 18:48 Noah：几个核心运算各对表做什么（原话）

> 所以 miniKanren 的几个核心运算，fresh 创建新变量，run 提供初始代换这张表用，以及最后要查询的几个变量，合一给表插入，合取析取将两张表合并？

Claude 的回答（未经确认）：大体对，但这句话里的「表」是两个层次的表。「合一给表插入」说的是代换（一行）；「合取析取将两张表合并」说的是每个目标各自描述的表。分开成两种读法，各自一致：

| 运算 | 静态：每个目标各有一张表（数学层） | 动态：一张答案表被逐步加工（实现层，每行是一个代换） |
|---|---|---|
| `≡` | 相等的表 | 逐行填格子、连格子；矛盾的行删掉 |
| 合取 | 两张表在共同的列上对齐，只留对得上的行 | 先后加工：前一个交出的每一行，接着交给后一个 |
| 析取 | 两张表上下叠 | 同一行交给两边各自加工，结果叠在一起 |
| `fresh` | 用完以后去掉这一列 | 加一列空白 |
| `run` | 只留查询的那几列 | 从只有一行空白的表开始；最后读出查询的列 |

动态读法里合取不是「合并」，是接力；两种读法得到同一张表，这就是「与」在两层读法不同（交与复合）的表的版本。

### 10/4 13:43 Astra 的核对（全文在 `reviews/astra-art5-goal-relation-2026-10-04.md`）

**结论**：核心成立，可以据此设计正文。但要分清三层：目标交出的**原始代换**、从代换读出的**查询答案**、答案表示的**数学解集**。「相同」「可交换」在这三层上不是同一个断言。

**以后正文要用的说法（按 Astra 的限定改写）**
- 点题句：在这个实现里，忽略结果的顺序和重复，一个目标可以看作代换之间的二元关系：它把一个输入代换关联到零个或多个成功的输出代换。不说「这就是 miniKanren 的全部本质」（别的实现还有变量计数器、约束存储等状态）。
- 两层的对应：对这里的三角形查询，一组边在关系里，当且仅当它是某个成功答案。一般地，查询还可能交出带未知项的答案，一个答案代表一族满足条件的值（一个具体元组满足关系，当且仅当它是某个成功答案的具体实例）。正文只展示确定的答案，「当且仅当」要限定为「对这里的查询」。`run*` 说「收集各个成功代换读出的查询答案」，不说先收齐再读。
- amb 与复合：在本文的 amb 搜索里，过程沿用普通函数的参数和调用方式；把两个过程按普通调用接起来，后一个会继续处理前一个的每个成功结果，所以实现了关系的复合。依赖 `collect` 的边界和搜索解释。等式：`(collect (λ () (g2 (g1 s)))) = (append-map (λ (t) (collect (λ () (g2 t)))) (collect (λ () (g1 s))))`，限于纯、有限的搜索。使用 amb 的过程不再是数学上的函数。
- 合取的两种说法：对代换之间的关系，合取是复合（存在中间的代换 u）；对满足条件的赋值集合，合取是交集。两层对得上，是因为纯关系式目标在原有信息上继续施加条件；这还要求各原语正确实现其条件，任意手写的 `Goal` 未必满足。
- 可交换（**原来的第 9 条不成立，是 Claude 加的推论**）：「只增不改」推不出交换性。能说的是：对由合一、合取、析取和新变量构成的纯关系式目标，搜索完整终止时，交换合取两侧不改变它们表示的解集；原始代换、答案排列和执行代价可能不同。已复现：`x ≡ y` 再 `y ≡ 3` 得 `{x ↦ y, y ↦ 3}`，反过来得 `{y ↦ 3, x ↦ 3}`；两个析取换序，答案从 `((1 3) (1 4) (2 3) (2 4))` 变成 `((1 3) (2 3) (1 4) (2 4))`。递归关系交换后可能不终止；任何检查代换的宿主代码都会让顺序可见，不限于 `≤ᵒ`、`pythᵒ`。
- 只增不改：对本文这些原语构成的目标成立，不是 `Goal` 类型保证的；可以原样成功，不一定严格增加。
- 保留顺序和重复：只对本文的 `choose` / `collect` 与相应的有限列表实现成立，不能推广到任意流策略与任意 amb 策略（`mplus` 交出 `(a b c d)`，`mplusi` 交出 `(a c b d)`）。
- `bind` 与 `∘ℒ`：`bind` 是流上的有序展平映射，`∘ℒ` 是借它连接两个函数的运算，不是同一个函数。
- 代换与环境：区别不只在能存另一个变量，还在变量身份（`eq?`，不是打印出来的名字）、递归解引用和合一规则。
- 04 的元组与代换（**第 13、15 条说轻了，也是 Claude 加的**）：元组保存各阶段需要的具体值，会丢弃信息（`(l h)` → `(a h)` 丢了 l）；代换把这种信息传递推广为对逻辑变量及其联系的统一记录，不是简单换两头的数据类型。从挑边的一步到目标要多做三件事：从输入代换读出边界当前的值；选一个候选；把候选与目标项合一（目标项若已确定或与别的项共享变量，要检查兼容，不能覆盖）。「07 只是确定两头的东西」过轻：合一新增的是解释和维护信息的规则，amb 提供的是遍历选择的机制，二者合起来才是这门语言。

## 五、创作者笔记（不进正文，除非某一节真的用得上）

**表的更多读法**
- 函数是键唯一的表；谓词相当于给「所有可能的行」添一列布尔值，标着 `#t` 的那部分就是关系；存容器的函数摊开就是关系的表。关系的两种表示（谓词、交出列表的函数）都可以读成函数的表。不对称：由交出列表的函数得到谓词只要一次 `member`，反过来还缺候选从哪里来。
- n 列的表是 n 元关系；「几元只是看成几组」（Rel compact closed，Rel(X, Y) ≅ Rel(1, X × Y)）。填列就是部分应用：`(λ (c) (pyth? 3 4 c))` 是一元关系，`(λ () (pyth? 3 4 5))` 是零元关系，零元谓词即 `(→ Boolean)`，纯的只有两种，正是两个布尔值。若用，候选位置是 §8 讲空合取、空析取处；只在数学层面说（列表层面 `(run* () …)` 可交出 `'(() ())`）。
- 结果树：嵌套的 `for/list` 保留分支层次（已执行 `#:when`，不是搜索过程的记录）；压平即 `append-map`。1 到 20：8000 个组合 → 1540 个候选 → 六个答案。
- 顺序：列表里行的先后是叶子被走到的先后；这棵树叶子同层，深度优先与逐层展开交出的顺序相同，只是干活的顺序不同（`∘ℒ` 逐层，`choose` 深度优先）；叶子深度不齐或分支无穷时才不同。

**关系代数与关系演算**
- 同一张表有两种谈法：代数（整张表的运算：筛选、投影、连接、并、差）与演算（写出一行要满足的条件：∧、∃、=）。Codd 证明两者在基本范围内表达力相同。SQL 写出来像演算，执行时转成代数。逻辑式编程在演算这一边；Datalog 是过渡。
- 本篇两种都有：§3、§4 的假想语言是演算的写法；§5 的 `∘ℒ` 是代数的写法（复合 = 在中间那组列上连接，再投影掉）；§7 的 `choose` 回到一行一行地找。
- 对照：并列的目标共享未知项 ↔ 连接；`fresh` 引入而不交出的项 ↔ 投影掉的列；`==`、`pytho` ↔ 筛选；`disj` ↔ 并；`run*` 的未知项 ↔ 最后的投影。
- 类比断开处：数据库的表有限、存下来，这里的关系由条件定义、现场计算、可以无穷；SQL 默认不去重、不保证顺序；数据库有优化器，这门语言按序深度优先；逻辑变量可绑定到部分结构（合一）；递归；否定（差）本篇不碰。
- 正文不用「关系代数」「关系演算」这两个词。

**「构造一张表」与构造逻辑（Noah 10/3 问起）**
- 对应的不是构造逻辑。构造逻辑对上的是函数式那一支：命题是类型，证明是程序，运行是化简证明。关系语言是另一支：程序是一组公式，查询是带存在量词的公式，运行是找证明，答案是证明里给出的见证。
- 接点只有「说存在就得拿出见证」：`run*` 交出的每一行都是一个见证。这门语言只用到 =、∧、∨、∃、⊤、⊥（§8 的对应表正好是这几行），没有否定和全称；在这一小块里，经典逻辑与构造逻辑能证出的东西相同，所以「构造」二字在这里区分不出什么。正文不提。
- 「构造一张表」更实在的读法是由小表造大表，见上一条「关系代数与关系演算」里的对照。v5.4 把其中复合的那一句放进 §4。

**范畴论侧**（详见 `archive/art5-plan.v4.9.md` 与 `art6-plan.md` 第七节）
- 四个范畴：Host、Host_amb、Rel、Kl(List)。Kl(List) → Rel 取支撑，保持复合，不忠实；`Host_amb ≃ Kl(List)` 只在受限意义下成立（有限终止、无其他效应、延续可多次调用、按 `collect` 的列表观察、一阶数据）。与第二篇只能说「都在直接风格与显式编码之间往返」，不说三个世界同形，Rel 不对应 𝒰。
- 两种表示之间的往返（Noah 10/2）：`f : a → (Listof b)` 与用 `choose` 写的 `g : a → b` 互相得到，`g = (λ (a) (choose (f a)))`，`f = (λ (a) (collect (λ () (g a))))`；用 amb 库的写法就是 `for/amb` 与 `in-amb`，看上去是两种容器之间的转换。这一对就是 reflect / reify（Astra 第一轮写作 `reflect-arrow` / `reify-arrow`）。列表 → `choose` → 列表逐字还原（顺序与重数都在）；`choose` → 列表 → `choose` 在上面的受限意义下不可区分；两个方向都保持单位与复合（收回两段的普通 `∘`，等于各自收回以后的 `∘ℒ`）。代码见「附-d」。与第二篇的对应：`choose : (Listof a) → a` 与 `call/cc : ¬¬a → a` 同形，都把显式编码里的值放回直接风格（`uncps` 用的就是 `call/cc`）；`collect` 与 `cps` 同向，把直接风格的计算收成编码。区别：amb 的「容器」不是一个值，只有站在 `collect` 的边界上才看得见它的全部元素；边界之内的程序始终身处其中一个元素。正文不点破，留给第六篇（reflect / reify）。
- Rel 是 quantaloid；列表侧 `disj` 是有序追加；列表复合只对一侧分配；`conj` 按解集是 ∧（取交的是解集，不是代换上的关系）。
- 交错合取只在忽略顺序时满足结合律（有限纯情形）。
- 状态与非确定性：这个实现把代换状态与非确定性搜索接在一起；不说「逻辑式编程是状态与非确定性的组合」。

**amb 在第五篇里放多少（10/2 晚，Noah 问起；Claude 的看法，未定）**
- 第五篇的 `choose` / `fail` / `collect` 已经是一个最小的 amb：再加三行语法（`amb`、`for/amb`、`in-amb`）就能逐字跑出 amb 库文档里所有有限、深度优先的例子。它做不到的恰好是三件事：只要第一组、无穷的备选、换搜索的走法，也就是本篇「未解的线索」。
- amb 库 v2 与它的差别可以压成一句：`choose` 不再自己调用 `k`。第五篇是 `(shift k (append-map k p*))`，等待的工作留在宿主栈上；库是 `(shift-at tag k (amb-tree k …))`，把 `k` 交到边界，由边界上的循环拿着一张待办（frontier，第四篇的「前沿」）决定先走哪个，答案以惰性的流交出。压到最小约二十行，结果与库相同（取第一组直角三角形都是试到第 420 组候选就停；广度优先的顺序相同）。库的其余复杂度是工程上的：公平、多值、shuffler、向量压缩、不定长 `for/amb` 的协程写法（另用了一个 prompt tag）。
- control-context 文档里 call/cc 的 amb 没有 `in-amb`，因为没有边界：它天然是「找到第一个答案就往下走，想要下一个再 `(amb)`」。要补 `in-amb`，得用逃逸延续手搭一个边界，答案靠可变状态记下。三者正好互补：call/cc 版天然只要第一组，收齐要手搭边界；第五篇的 `choose` 天然收齐，只要第一组做不到；库 v2 有边界、有显式的待办、有惰性的流，两样都行。
- 文档那一版另有一个限制：备选本身又是 amb 时会丢答案，`(amb 1 (amb 2 3) (amb 4 5 6) 7 8)` 只得到 1 2 3 7 8（内层 amb 在外层生成器的 `get` 里求值，捕获的延续带着 `(set! s (stream-rest s))`，重入几次流就多前进几格）。
