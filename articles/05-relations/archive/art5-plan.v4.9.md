## 一、主线

**一句话**：搜索程序本来就在描述关系。关系能检验（谓词）、能收集答案（列表），但要像关系那样复合，就得有人承担中间项的搜索：§1 由写程序的人手写循环，§4 交给列表世界的 `append-map`，§5 交给 `choose` 捕获的延续，这时普通函数 `a → b` 就能当关系用、普通 `∘` 又能复合了；§6 再用代换记下未知项之间的信息，§2 那门假想的关系语言就真的跑起来。最后，用户想「找到一组就够了」，`abort` 却只结束了当前备选，其他备选仍在 `append-map` 里等着：现有接口没有区分这两种退出目标。

**直接风格与显式编码之间的往返**（v4.2 按 Astra 审阅改：不说「三个世界同形」）：
- 正文造出的是：纯函数（Host）、带 `choose` 的函数 `a → b`（直接风格，§5）、`a → (Listof b)`（显式编码，§4），再加上数学上想要的关系（§2）。
- 与第二篇的对应只到这一层：带 `choose` 的函数 ↔ 𝒞，列表世界 ↔ 𝒦，纯函数 ↔ 构造性宿主。**Rel 不对应 𝒰**：`flip` 无损，取支撑丢信息；𝒰 在这里没有对应物，Rel 在第二篇也没有。
- 可以说「两篇都在直接风格与显式编码之间往返」；第五篇正文不宣布这个对应，第六篇也只按这个限度说。
- `Host_amb ≃ Kl(List)` 只在受限意义下成立：有限且终止、无其他可观察效应、延续可多次调用、按 `collect` 的列表观察（含顺序与重数）、使用者只经 `choose`/`fail`/`collect` 接口、一阶数据。两个方向：`(reify-arrow f) = (λ (x) (collect (λ () (f x))))`，`(reflect-arrow g) = (λ (x) (choose (g x)))`；前者接后者还原列表箭头，另一方向按观察等价理解。

**搜索由谁承担**（贯穿全篇的问句）：手写循环（§1）→ 语言（§2，假想）→ `append-map`（§4）→ 捕获的延续（§5）→ `choose` 管分支、代换管共享信息（§6）。
- 准确性：`fresh` 本身不搜索，它只引入未知项；找到它交给目标的运行（原型里是 `betweeno` 中的 `choose`）。草稿「找中间项的搜索，交给了 `fresh`」要改成「中间项由 `fresh` 引入，如何找到它交给这些目标的运行」。

**轴线**
- 明轴（第四篇原话）：同一份剩余工作为每个备选各运行一次。`(append (k 1) (k 2) … (k 20))`；与第三篇例四的串联对照。
- 暗轴：绑定语法与捕获算子。§1 `let*`、`for*` 用语法构造局部延续，只差调用次数；§5 `choose` 在运行时捕获同一个局部延续。兑现（两段程序并排）留给第六篇。
- 暗轴：分支与共享信息。§6 新增的是第二件事：搜索找到的信息怎样记在未知项之间。正文只说行为：「每条分支带着自己的代换往下走；一条分支失败，不会改动其他分支手里的代换。」**不写**「逻辑式编程是状态与非确定性的组合」（概括过大：普通状态加非确定性不会自动产生逻辑变量、合一与关系语义）；至多「这个实现把代换状态与非确定性搜索接在一起」。

**适用范围**：开头声明一次，本篇只讨论有限的搜索，指**整个搜索过程能够完成**（有限个答案与搜索终止不是同一个条件）。

### §2 关系（v4.9，现行；草稿 rev 129）

主线：树 → 表 → 关系 → 关系的两种函数表示。没有伪代码。

1. **开场钩子**：保留 Noah 改过的那段（`right-triangles` 交出的是装有全部答案的容器，值从一个结果扩大成所有结果，描述的是 `(l h)` 与 `(a b c)` 之间的关系）。
2. **把树的形状留下来**：§1 的代码里没有树这份数据，树只是 `k` 被调用的形状。嵌套的 `for/list`（§1 说过它交出列表的列表）保留了分支层次：`right-triangles/tree`，展示 `(right-triangles/tree 1 5)`（代码 §2-a）。它是结果树，不是搜索过程的记录。
3. **压平成表**：把每一层交出的列表接起来（`for*/list` 多做的事），空分支消失，`(right-triangles 1 5)` 只剩 `'((3 4 5))`。每条走通的路径是一行，行的先后是叶子被走到的先后；表是把所有走通的时间线并排摆出来的样子。
4. **认出关系**：这些行都满足条件，满足条件的也都在；表是「所有可能的行」（笛卡尔积，大表）的子集（小表）；暂且不计行的先后，就是关系；n 列即 n 元。
5. **函数是有唯一索引的表**：输入是索引，每个可能的输入恰好出现一次。
6. **关系的表没有这个保证**：以所有满足 a² + b² = c² 的行为例，列分成 `(a b)` 与 `c` 两组，拿 `(a b)` 来查有解时唯一，拿 `c` 来查可能找到好几行（例如 25）。把列分成两组来读的表叫二元关系；拿哪一组当索引去查另一组是挑的。
7. **重新写成函数的第一种办法**：拿整行当索引，给大表添一列布尔值，即谓词（`pyth?` 的类型）；标着 `#t` 的那张就是关系。三层循环加 `#:when` 就是列出大表的一块再筛（SQL `WHERE`）；提前剪枝：8000 个组合 → 1540 个候选 → 六个答案。大表列不完，布尔值挂在大表的行上，谓词交不出答案。
8. **第二种办法**：拿一部分列当索引，索引相同的行合并，表里存容器（数学上是集合，这里用列表；没有行的索引存空列表），即 `right-triangles`（`(right-triangles 1 4)` 交出 `'()`）。
9. **摊开容器**：每个元素配上索引，回到五列的表；前两列、后三列各成一组即二元关系，「几元，只是看成几组」。开头的结果树也靠展开嵌套容器得到表，只是每片叶子已记下路径上的三个值。集合记号（公式块，「暂且不计列表的顺序和重复」）。
10. **同一张五列小表用第一种办法写**：`→ℛ?`、`right-triangle?`（代码 §2-b）。一个存布尔值，一个存容器；不对称：有了 `right-triangles`，谓词只是一次 `member`，反过来还缺候选从哪里来。
11. **节尾**：谓词交不出答案，存容器的版本又得自己写循环去找。能不能只写下小表要满足的条件，让语言去把所有行找出来？

### §6 让关系语言跑起来

- **问题**：§5 的函数是有方向的。§2 的关系里，同一个未知项会出现在好几个约束里。缺的是「还不知道的项」本身，以及把找到的信息记在未知项之间的办法。
- **共享未知项的小例子（v4.2 新增，Astra 建议 + 本篇现成场景）**：(a) 里的 `a` 同时出现在 `(betweeno l a h)` 与 `(betweeno a b h)`。若每次出现各自 `choose` 一次，两个 `a` 互不相干，答案会错（例如出现 `(4 3 5)`：前一个 `a` 取 4，后一个取 3）。要点在于：§5 的直接风格里 `a` 由宿主的 `let*` 绑定一次，共享是白给的；关系语言里每个约束是一个单独的目标，`a` 的值在一个目标里找到，却要让别的目标看见，就得有个地方记下来，并沿着 `conj` 传下去，这就是代换。演示代码待写（重排代码时做）。先让读者看到为什么不能把未知项当作每次独立的 `choose`，再引入代换。
- **逻辑变量与代换**：`var`；代换（`hasheq`）；`walk`；`unify`（失配时 `(fail)`）；`walk*`。完整的序对合一。
  - **occurs 检查：补上（v4.2 定）**，约 6 行。理由：`==` 出错时读者很难察觉；不补则 `(== q (cons 'a q))` 被接受，输出时 `walk*` 还可能不停机。
  - **未确定变量不重整（v4.2 定）**：正文展示的最终答案都已确定（`swapo` 也满足）；一句限定即可。
- **目标是「代换 → 代换」**：`==` 即合一；`conj` 依次应用，与 §5 的普通 `∘` 同一件事；`disj` 用 `choose` 选一个目标；`fresh` **在收到代换时才分配变量**（原型已改，Astra【必须改】：否则同一目标重复使用会共享变量，递归关系如 `appendo` 在构造时就提前展开）；`run*` 用 `collect` 收集。
  - **`conj` 与 ∧（v4.2 改正）**：取交的是约束的**解集**，不是代换上的关系本身（「令 x=1」与「令 y=2」两条代换关系直接取交，不等于先后运行）。正文一句：「前一个目标交出满足自身条件的代换，后一个在这些代换上继续求解；最后留下的答案，就同时满足两个条件。」不用「闭包算子」补救。创作者备注：充分条件是 ⋃_{t∈g(s)} D(t) = D(s) ∩ ⟦φ⟧（D(s) 为代换 s 允许的完整赋值集合），并隐藏局部变量、忽略重复、按意义比较代换。
  - **分支与共享信息**：「每条分支带着自己的代换往下走；一条分支失败，不会改动其他分支手里的代换。」
- **两个只认数的目标**：`betweeno`、`pytho` 要求参数已确定，所以目标的顺序有关系。§2 已不再承诺 `pytho` 反向求解。
- **§2 伪代码原样运行**：(a) 与 (b)，结果与 §1 相同。
- **对应表（v4.2 按 Astra 改）**：

  | 写法 | 数学意义 | 限定 |

  | `(conj)` | ⊤ | 恒等目标 |
  | `(disj)` | ⊥ | 不产出代换（`fail` 是零参数控制操作，不是目标，不进表） |

### §7 `run 1`：退出了当前备选，没退出搜索（结尾）

- **用户意图写死**：找一组就够了。最直接的写法：`run` 的 `reset` 里，得到第一个答案就 `(abort (list answer))`。
- **现象**（`proto/run1.rkt`）：交出全部六组，没有报错。**而且去掉 `abort`，结果一模一样**（`abort` 已在局部计算的尾位置）：它根本没碰到想丢弃的工作。最小机制：`(reset (let ([x (choose '(1 2 3))]) (abort (list x)) (error 'unreachable)))` 得 `(1 2 3)`，错误被跳过，其他备选照常运行。
- **第五篇给出局部诊断（v4.2 定）**：「它结束了当前备选的计算，却没有丢弃等待其他备选的 `append-map`。」回到 §5 日志处「其余备选在 `append-map` 里等着」。第三篇已给过 `k` 自带边界的规约，读者有条件理解。然后留下问题：怎样退出整个搜索？

### 关系的两种表示（9/29，原「单子的读法」下）

- **关系的两种表示（9/29）**：同一个关系可以写成谓词（特征函数，给齐参数回答在不在关系里，例如 `pyth?`），也可以写成 `→ℒ` 箭头（给定一端，列出所有相关的另一端，例如 `divisors`）。一个检验，一个生成。谓词精确，不记顺序与重数，但不能枚举，也不能直接复合（复合要对中间项求「存在」，即一次搜索）；列表能枚举、能复合，代价是多记了顺序与重数。列表世界值得造，理由来自关系本身：它把复合所需的中间搜索装进了 `∘ℒ` 里的 `append-map`。
  - 谓词本身也是一支 `→ℒ` 箭头，值只有零个或一个元素：`(if (pyth? a b c) '(ok) '())`。这正是 §1「过滤就是零个备选」成立的原因。
  - 措辞：说「搜索这类程序本来就在描述关系」，不说「用关系描述程序」这样的总纲；仍守「列表只模拟关系」。
  - 方向：谓词不分输入输出，`→ℒ` 箭头有方向，同一个关系可有几种箭头读法。正文至多带一句，不展开（展开就滑向逻辑式编程，留给第六篇）。〔v4.0：现在由本篇 §5 承接〕

### v3.7.4 的 §1–§3 设计（原文）

#### §1 遍历搜索（开场）

从程序员熟悉的暴力搜索进入（与前四篇第一节的惯例一致：第二篇 `fact`/`fib`、第三篇函数调用、第四篇递归改循环），不顺着第四篇写；第四篇的线头（`if` 的「写两次、跑一次」、「搜索树」一词）放在开篇承接语里，承接语最后一句把搜索树落到嵌套循环上。

嵌套循环枚举勾股数，`for*/list`。然后把 `*` 悄悄做的事摊开：每一层的剩余工作写成显式的局部延续 `k`，交给每个备选各跑一次（`choose/k`）。输出与 `for*/list` 逐字相同。代码：§1-a、§1-b。

素材：
- **`for*` 是会分岔的 `let*`（9/29 午，§1 的主干）**：`for*/list` 之后、摊开之前，从 `let*` 讲起。第二篇给过脱糖 `(let ([v e]) b) ≡ ((λ (v) b) e)`：每个绑定背后藏着局部延续 `(λ (v) b)`，在一个值上调用一次；`for*` 的每个子句背后也有一个，对列表里每个元素各调用一次，结果接起来。于是「把剩余工作拿出来写成显式的 `k`」有了来由；摊开后点一句：`append-map` 站在 `let` 脱糖里函数应用的位置上。脱糖只在散文里回指，不另放代码块，不需要新代码。
  - 三级对照：`if` 写两次、跑一次；`let*` 写一次、跑一次，一条时间线；`for*` 写一次、跑 n 次，n 条时间线，n 可以是零（过滤）。时间线那段以 `let*` 为对照，再与第三篇例四的串联对照。
  - 两者都固定执行顺序：`let*` 从上到下；`for*` 另外固定了备选的先后，即「深度优先」那句。
  - **`for*/list` 不是嵌套的 `for/list`（9/29）**：嵌套的 `for/list` 得到列表的列表，`for*/list` 每层把内层交出的列表接成一张，这一步就是 `append-map` 比 `map` 多做的事。§1 用散文点出（已写入草稿），不加代码块；它也说明最内层为何要自己返回列表。
  - 不预告 §2-j、§4、§5，不提单子与定界延续。`for*/list` 自动给主体套单位、`let*` 不套，这一差别留到 §2-j 交代，§1 不提。
- ~~**`pyth?` 是一个关系（9/29）**~~（9/29 午后撤回：§1 不点破，整条挪到 §2 开头）：`pyth?` 出现时点一句，它说的是 a、b、c 之间的一个关系。§1 末尾一两句：`for*/list` 加 `#:when` 把这个关系从检验变成了枚举（先生成候选，再用谓词检验）；这也是只讨论有限搜索的理由。不点破更多，不需要新代码。「两种表示」的对照留给 §2 开头。
- **if 与 choose**：if 消费一个已做出的选择，测试值先算出，未来写两次、跑一次（第四篇）；choose 的备选之间无值可选，全部进入。「确定性 = 未来是过去的函数」只在单次选择的关系读法下断裂；列表实现本身仍是确定的函数。修复是扩大值域，让未来落进一个列表：这是单子的出场动机。
- **兄弟节点**：第四篇 `rand*` 的兄弟各有各的延续；choose 的备选共享同一个延续。（9/29 起草：§1 只保留「备选共享同一个 `k`」本身，`rand*` 对照要先解释第四篇编译器内部，开场太重，已删；如需要，可挪到 §4 `choose` 捕获延续处。）
- **`k` 的调用不在尾位置**（9/29 起草时新增的观察，大纲外）：`k` 交出的列表还要和其余备选的结果接起来，所以其余备选在 `append-map` 里等着。它把「前沿记着还没开始跑的计算」落到具体事实上。是否留在 §1、还是挪到 §4-g 日志处，待 Noah 定（草稿里有评论）。
- **共享与重放**：§1 只指着 `(append-map k p*)` 说「未来每个备选各跑一遍」；日志挪到 §4（直接风格里 `before` 只写一次、`after` 出现三次，才成为现象，见 §4）。前沿的职责从「这次计算剩下的部分」变为「还没跑的那些计算」。

#### §2 关系（9/30 定：只讲「描述关系」，三层递进）

- **开场**：§1 的 `right-triangles` 给定 `(l h)`，交出的不是一个答案而是所有答案，它描述的是 `(l h)` 与 `(a b c)` 之间的关系；值从一个结果扩大成所有结果的列表（原 §1 节尾那句挪到这里）。不预告列表世界与规则。

- **第三层：关系也能表示成函数**。由 `(right-triangles l h)` 的定义（`run*` 包着 `right-triangleo`）认出：关系可以表示成函数，把与输入相关的所有输出收进一个容器。数学上是集合，这里为了方便用列表；注释一句「要处理无穷的搜索就得换成惰性的流，本篇只讨论有限搜索，列表就够了」（不点名 miniKanren）。
