# Astra：第五章后半大纲与关系世界的核对（2026-11-06）

> 提问见 `审核说明-后半大纲与关系世界-2026-11-06.md`。原文由 Noah 贴在文章仓库 PR #145 的评论里，照录。

核对了附件六个文件、PR head `0d0b28b` 的大纲，以及该版本 `code.rkt` 中的 `rel-min`。以下按审核说明回答数学与实现问题。核对方式是读码与推导，本次没有运行 Racket。附件提到的“Claude 的看法”文件未包含在 zip 中。

建议保留关系世界 ℛ，但先修正三个地方再写正文：ℛ 的恒等用合一；符号答案与有限分支关系分别限定；用实际的 `conde/condi` 与延迟机制描述搜索公平性。

## 问 1：主线与伴随

主线成立，适用条件要写全。为避免和本书 𝒞、𝒟 混淆，这里用基础世界 A、目标世界 E。

若 J:A→E 在对象上恒等且 J⊣U，令 T=UJ，就有自然双射 E(JX,Y)≅A(X,UY)=A(X,TY)。它保持恒等与复合，给出 E≅Kl(T)。**“在对象上恒等”加“有右伴随”已经足以推出这里的同构**；一般伴随的 Kleisli 比较只覆盖左伴随像中的对象。此前账本 10.17 那句“不是仅凭有右伴随推出”应读在“一般伴随”的语境，不能拿它否定这里已经加了对象条件的结论。Power–Robinson 的 Theorem 4.1 正是在说这个版本。

第五章可把三件事具体分开。

- 集合论模型。J:Set→Rel 把函数送到它的图，右伴随 U 在对象上给 U(Y)=P(Y)，在关系 R:X⇸Y 上给 U(R)(S)=⋃{R(x) | x∈S}。单位是单元素集合，余单位 P(Y)⇸Y 是成员关系。因此 Kl(P)≅Rel，同时 JU 是 Rel 上的余单子。
- 有限分支模型。换成每个输入只关联有限多个输出的 Rel_fin，右伴随换成 P_fin，相应有 Kl(P_fin)≅Rel_fin。
- 本章的具体列表实现。ℒ 是 Kl(List)，在既定的有限终止、纯搜索、按答案列表观察等条件下，ℬ 与 ℒ 对应。纯函数进入 ℬ 的 inj 对应 List 的单位注入，其右伴随在对象上给 List；把 ℬ 箭头 f 作用到一张输入列表上，需对各输入运行并收集 f，再连接列表。它不等于 Set→Rel 的幂集右伴随。由 ℒ 到 Rel_fin 的取支撑会丢掉顺序和重数。

所以这里宜说“选择目标计算世界以及纯程序进入它的方式，再寻找右伴随，由此取得纯宿主里的表示与复合”。实际语言的可定义程序、递归、错误和求值策略，还需限定到这套模型涵盖的片段。

## 问 2：ℛ 究竟取什么

前半的有限终止枚举按支撑确实落在 Rel_fin。后半若允许未定逻辑变量，则**有限个符号答案并不保证所描述的项关系有限分支**。

例如 `(define (anyᵒ x y) succeed)` 描述整个项域的乘积。项域无限时，对一个确定的 x 有无限多个 y。一次返回未定的 y 就能概括这些解；搜索只得到一个代换，仍不能据此说这个关系有限分支。两个位置的相等关系在每个固定输入上是单值的，但把两个位置一起作为查询，也能用一个带重复未知项的模式概括无限多组相等的值。

建议作者账本区分：

1. 前半的有限枚举模型 Rel_fin；
2. 后半 DSL 在有限树项上的关系指称，属于 Rel 中的可定义关系，可能有无限纤维；
3. 真正执行的是搜索代换与读出符号答案，能否枚举、是否完整、是否终止另看查询模式。

若仍统一叫 ℛ=Rel_fin，就必须限制允许的关系和输入模式，不能同时声称覆盖后半的一般符号关系。账本 2.1 对后半 ℛ 的限定在加入合一后需要同步更新。

## A—H，逐项核对

**1．需要限定。** 合法代换上的目标可以用 Subst×Subst 的关系描述其可能的成功转移，ℬ 代码返回一个代换、由搜索产生多个分支。额外绑定是约束的细化。Subst 应限于无环、键唯一且变量身份合法的状态；这个不变式不是类型别名本身保证的。另外 `fresh` 会分配新身份，原始状态若按对象身份逐字比较，应加新鲜名供给，或按新鲜变量重命名等价理解。

**2．语义上成立，理由须收准。** 对目标转移关系，合取是后一个目标接前一个目标，即 `conj g1 g2 = g2 ∘ g1`；析取在取支撑后是并。列表观察下，析取保留顺序与重复。仅凭“都住在同一个积里”不能推出合取应是复合——同一个积里的子集也能取交，复合来自目标收到并传出代换的接口。用户关系即便元数不同，也可以在统一的自由变量赋值空间里解释逻辑析取；在 Goal 层实现析取是本内核的选择。

**3．成立。** succeed 在状态层是恒等，fail 是空转移；分别是合取、析取的单位。保留条目 1 的状态与观察约定。

**4．层次区分成立，但要补上读出。** 用户关系是参数化的目标构造器；目标变换代换；代换是变量到项的有限绑定记录。附件所说“原始代换、读出的答案、数学解集”是另一条必须保留的区分，不能被这三个程序类型取代。多个不同原始代换可以读出同一答案，一个符号答案又可能代表多个数学解。

**5．语义对应成立，接口说法要改。** 在给定接口里 `succeed/fail : Goal`，它们已经是目标，没有先收零个 Term 再返回 Goal 的那一层调用。可说它们表达真、假，作为无自由变量的公式分别表示零元关系 {()}、∅；放到非空变量上下文里，真对应整个赋值空间。实现层分别是 Subst 上的恒等与空转移。

**6．Noah 的读法可以保留，并具体化。** 代换是一张键为未知项、值为项的有限表；条目表达等式，可能把未知项连到另一个未知项或含未知项的结构。它的语义是所有满足这些等式的赋值。建议把“记着哪些未知项已经有值”改为“记着已经建立的变量与项的等式”，因为 x↦y 并未确定 x 的具体值。

**7．“答案表的一行，有的列没填”不足以涵盖合一。** `{x↦y}` 的答案模式是 `(_.0 _.0)`，两列必须相等；空代换下查询 x、y 得到的模式 `(_.0 _.1)` 允许独立取值。两个例子都没有具体常量，“没填的列”不能表达它们的差别。只有查询列都已 ground 时，一个读出的答案才是一条具体元组。一般说“一个带等式约束的符号答案，概括一族元组”。Noah 的绑定表读法与这种答案模式读法可以同时存在。

**8．有限终止、采用相同深度优先顺序时可以比较；一般流实现不能直接认成原来的 ℒ。** 附件 `miniKanren-typed` 中 `all/conde` 走的是 `bind/mplus`，`alli/condi` 才走 `bindi/mplusi`。有限流全部展开以后，前一组能对应 List 的追加与 bind。加入无限流、交错或停机观察，就超出了前半 gather/scatter 的可逆范围，也不能直接搬用 List 的运算律。流的类型形状本身还没有指定复合与相等标准。

**9．成立但须分开三个步骤。** run* 对空代换运行目标、收集成功状态、walk*/reify 查询项。按数学解集看，隐藏局部变量对应存在量化与投影；投影后相同行归并。实际列表可能重复，reify 给的是答案模式，run* 还可能不终止。fresh 负责变量作用域与存在量化，原始代换通常仍保留局部变量的绑定；“遮列”发生在指称及查询观察上。

**10．需要限定。** 纯合一关系在逻辑上不指定输入输出方向，appendᵒ 的拆分查询是好例子。但含递归、合取、析取的关系，换查询方向或子句顺序可能改变终止性与能到达的答案。请写“可提出反向查询，本例能算出四组拆分”，不要由使用 == 推出任意方向都能跑完。function->relation 需要其输入位置已 ground，输出位置可以未知；predicate->relation 通常要求所有参数 ground。若只用 walk 读取含变量的复合项，还需 walk* 及 ground 检查。

**11．相等的指称是对角线，但 == 的目标转移不是 Subst 上的对角线。** 二元关系 `(λ (x y) (== x y))` 在项值域上是相等。具体公式 `(== t1 t2)` 则筛选使两项相等的赋值；例如 `(== x 1)` 描述 x=1。unify 可能扩展代换，所以不能把它在状态层的作用称为恒等。

**12．保留 ℛ，但定义其箭头及相等标准。** 可以把项上的可定义二元关系作为箭头，按解集相等比较，要求对下述复合封闭且包含相等关系。这样得到 Rel 的一个子范畴（只取一个项域时，是单对象版本）。程序本身另有顺序、重复、停机等观察；“真正基于关系”不能自动赋予实现 Rel 的全部规律或表达能力。

**13．在关系指称层成立。** `(fresh (y) (P x y) (Q y z))` 正是 ∃y.(P(x,y)∧Q(y,z))，所以定义了关系复合。实际执行仍按 P 后 Q 搜索，需防止变量捕获并保持新鲜性。结合律是在相同外部解集的意义下说；不能由此推出原始代换的表示和名字逐字相同。

**14．四步正向例子可行；单位须改。** 对 ground 输入、有限纯搜索、解开全部输入项并用 unify 约束输出的包装，四步能按原顺序给出相同的 ground 答案，取支撑后保持关系复合。ℛ 的单位应写成
```racket
(define (idᵒ x y) (== x y))
```
若 function->relation 要求输入已知，`(function->relation values)` 就不是全查询模式的 idᵒ。当前 code.rkt 的 rel-min 会先 value-of 输入，未知时直接报错。即使用合一替换输出 record，也不会自动补上输入端的这个能力。反例（按完整关系内核接口）：
```racket
(define (P x y) (== y 1))
(run* (q) ((∘ᵒ P (function->relation values)) q 1))
```
关系恒等律要求它与 `(run* (q) (P q 1))` 有同一解集；包装 values 的第一步却要求 q 已知。可以说它在允许的正向模式下实现相等关系，不能据此把接口等同于全模式的关系恒等。也不能把两者按 ground 图等同以后，仍让那些会观察 groundness 的调用上下文任意使用它们。

**15．交换图可以保留，但标清观察层次，避免画成三边互逆。** 一个稳妥的图是
- ℬ ↔ ℒ，gather/scatter，在前半有限纯搜索、列表观察的范围互逆；
- ℒ → Rel_fin，逐输入取列表支撑；
- ℬ → Rel_fin，先 gather 再取支撑。三角形因此交换。
- ℬ → ℛ 的 function->relation 是带输入模式的实现包装，在既定正向 ground 查询中核对答案；ℒ → ℛ 可先 scatter 再包装。
- ℛ 的程序 → 关系指称，需读出查询项、解释剩余变量、忘掉顺序重复。前述两条包装路线在适用片段具有相同指称。

一般 ℛ→ℒ 或 ℛ→ℬ 没有这里已经给出的全域逆变换。只有输出可有限、完整枚举的 ground 查询才适用；带未定变量的符号答案不能直接充当全部 ground 元组列表。ℛ 的关系结合律与单位律在解集层成立；要比较具体答案列表，必须另核搜索顺序。原始状态通常连多出的 fresh 绑定都不同。

**16．逻辑表在解集层基本成立，需修两行并注明列域。** == 一行按第 11 条写成“使两项相等的赋值”，二元相等本身才是对角线。run* 一行写成“查询的符号答案列表，其 ground 实例表示所找到的解”，只在 ground、完整终止并去重以后才可直接称整张表。合取对应自然连接，无共有变量时是积；同一变量表头时是交。析取取并要求相同表头，变量集合不同时先扩展到共同赋值空间。fresh 对应投影，顶与底对应零元表。这可以认作关系代数的正片段；遇到无限域、非 ground 模式与递归，要区别有限数据库的物化表。仅有这些对应还不能把任意关系程序称为总会找到见证的构造性证明。

**17．“差的是交错”说得过满。** 可以说 demo 用 amb 承担分支与回溯，用普通复合串联目标，因而省掉了显式的 mplus/bind。和原始 microKanren 还有新鲜变量管理、延迟协议、答案消费以及 occurs check 的差别。原始公开内核的 ext-s 没有 occurs check，附件 demo 有；写成本章选择有限无环项即可。demo 按对象身份分配变量，原内核显式保存计数器。若本章照 demo 写“microKanren 风格的小内核”，读者能准确知道比较的是哪些构件。

**18．按当前附件，例子不能直接支持“流版能返回 1”。** 定义
```racket
(define (nevero) (fresh () (nevero)))
```
后，demo 的深度优先 conde 会堵在第一支。附件 miniKanren-typed 的 conde 同样用深度优先 mplus。甚至换成 condi，ifi 也须先求出 `((all g0 g1) s)` 才调用 mplusi；nevero 在交出第一个流节点之前就不返回，交错器仍没拿到可轮换的节点。该 Streamof 只有空、单值盒、以及“一个答案加延迟尾”，没有“尚未产出答案但可让出控制”的独立节点。

若要保留此反例，应同时给出能把递归搜索暂停成独立 thunk 的流表示及相应调度。原始 microKanren 的 mplus/bind 会处理 procedure? 的未成熟流，但调用方仍要在递归处提供延迟；单靠容器换成流不够。否则可换一个不断交出答案的左分支，比较 conde 与 condi 是否能轮到右分支，并单列答案前发散这个更强的限制。

## 直接影响后续代码的两项检查

- demo 的 run/run* 只支持一个查询项 `(x)`，4.1 示例写的是 `(a b c)`。搬内核时要扩展查询语法，并把整个查询元组一起 walk*/reify。若逐项单独 reify，x=y 与 x、y 独立都可能分别打印成 _.0，丢掉共享信息。
- demo 用的是 typed/amb 的可逐个消费序列。换成本章 `(reset (list ...))` 配 append-map 的 eager in-amb，run 1 仍会先完成整个收集，才在列表上截取一个答案。只要有限 run* 可按这个简化写，但“只要第一组”或 nevero 的实验必须明确使用哪种 in-amb。

数学上无需为了上述问题删掉第 6 节，也无需由这些检查决定 4.3 是否保留无合一中间版。需要先定的是 ℛ 的指称范围、包装器的输入模式，以及用什么观察判定“同一个关系”；这三项定了，交换图和示例才能一致。
