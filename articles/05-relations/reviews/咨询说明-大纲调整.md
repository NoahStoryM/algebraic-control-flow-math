## 二、前三节现在是什么样（相对你上次看到的版本，变化很大）

主线只有一条：**表**。把问题建模成关系，也就是一张表。

**01 遍历搜索**
- 三层 `for*/list` 找直角三角形，`(right-triangles 1 20)` 交出六组，试了 C(20+3-1, 3) = 1540 组。
- `right-triangles` 是纯函数，所以可以缓存。缓存的代码进了正文：`(define-type (Dict k v) (Listof (Pair k v)))`，`cache` 是一张以边界为键的关联列表，值是答案的列表。
- 设想把所有边界都算过一遍，`cache` 就是一张巨大的表；调用函数求值，就是按键查表。结论：任何纯函数都可以看作一张以输入为键的表。

**02 关系**
- `(Dict k v)` 的定义本身并不要求 `k` 是键。放开这个限制，把 `cache` 摊开成 `rows`，每组答案各自配上它的边界，类型是 `(Listof (Pair Bounds Triangle))`。
- 行的先后不关心，换用集合来记：R = {((l, h), (a, b, c)) ∈ (ℕ⁺ × ℕ⁺) × (ℕ⁺ × ℕ⁺ × ℕ⁺) ∣ l ≤ a ≤ b ≤ c ≤ h ∧ a² + b² = c²}。竖线左边的笛卡尔积是行的形状，右边是条件；R 是笛卡尔积的子集，这就是关系。
- 纯函数也是关系：{(a, b) ∈ A × B ∣ b = f(a)}，条件是每个输入都有唯一的输出。
- N 列的表对应 N 元关系；二元关系；结合律，R 也是五元关系；一元关系是子集；零元关系只有 `{}` 和 `{()}`。
- 谓词把这几种关系连起来：作为函数它是二元关系（所有元素排成一张大表，再加一列布尔值）；把笛卡尔积整体看作一个集合，它在判断输入是不是某个子集的元素；N 个参数的谓词描述一个 N 元关系；零个参数的谓词只有 `(λ () #t)` 和 `(λ () #f)`，对应两个零元关系。

**03 描述关系的语言（短稿，约 300 字）**
- 谓词是函数，只能按键查表：给它一组数，它回答是或否。我们要的是反过来，找出所有值为 `#t` 的行；函数做不到，只能自己把候选一组组列出来去问，第一节的三层循环做的就是这件事。能不能只写条件，让语言去找行？
- 设想有一门语言，可以直接写关系。谓词 `pyth?` 和 `<=` 各有对应的关系 `pytho` 和 `≤`，写法一样，只是参数可以是还不知道的数。
- 给定边界 l、h，R 剩下的是 {(a, b, c) ∈ ℕ⁺ × ℕ⁺ × ℕ⁺ ∣ (l ≤ a ≤ b ≤ c ≤ h) ∧ (a² + b² = c²)}，照着写下来：

```racket
(define (right-triangles l h)
  (run* (a b c)
    (≤ l a b c h)       ; l ≤ a ≤ b ≤ c ≤ h
    (pytho a b c)))     ; a² + b² = c²
```

- `run*` 对应集合的花括号。这还只是伪代码，结果是后面实现以后跑出来的。
- 这一节**有意不出现**：miniKanren 这个名字（留到后面认出来）、「目标」、`Term`、`Goal`、对照表、`fresh`、`≡`。`≤` 和 `pytho` 只用不定义。

已经定下的实现方向：尽量与官方 miniKanren 的行为一致（`≡` 就是合一，不做算术），实现基于 Noah 的 `ambKanren/demo.rkt`（用 amb 写的极简 miniKanren，`Goal = Substitution → Substitution`，`disj` 是 `amb`，`conj` 是函数复合）。

## 三、Noah 的新主线（10/3 22:40 的原话）

> 我觉得大纲估计要调整一下。现在的叙事是用伪代码描述数学，而数学语言能直接解决直角三角形问题。伪代码给了，所以后面的叙事主线应该是怎么实现这门语言。
>
> 这门语言的核心是关系，所以要实现这门语言，首先要实现关系。最简单的思路，关系就是一张表。然而我们只能构造有限的数据结构，所以没办法直接用一个数据结构来表示关系。比如说 add1 函数，作为纯函数，它也对应一张表，但是显然我们不可能把这张表完整构造出来。那么能不能直接用函数来表示关系呢？可以，虽然函数是特殊的二元关系，但是可以把相同的输入对应的不同答案收集起来用一个容器装载，这就是我们开篇做的事情。
>
> 之后要怎么叙事，我就有点想不明白了。
>
> 后面部分有一段叙事，就是 for*/list 和 let* 对比，局部延续，多时间线，choose/k，再通过定界延续抹除 choose/k 的延续参数，得到 choose fail collect 认出是 amb。意识到有了 amb，任意函数都是一个二元关系。无 amb 的宿主 𝒮，有 amb 的宿主 ℛ，以及之前用 List 收集答案模拟二元关系的 ℒ 之间的联系。最后实现 miniKanren。
>
> 大概思路是这样的，几个难点没想好怎么处理。

他随后的补充（22:49）：

> 目前的 miniKanren 代码是基于数学语言的：`(run* (a b c) (≤ l a b c h) (pytho a b c))`。而之后叙事意识到可以用返回 List 的函数来表示二元关系，开头我们就这么做了。而开头其实是把边界划分用三步处理：l ≤ a ≤ h；a ≤ b ≤ h；b ≤ c ≤ h。所以实际上开头就是涉及到关系的复合，复合得到 l ≤ a ≤ b ≤ c ≤ h，所以分析实际计算顺序，看是怎么复合的，以及之后的 ∘ℒ 都有动机了。

（第三步他原话写的是「a ≤ b ≤ c」，应是笔误。初稿 §5 里已经有这四步在列表世界里的写法：`pick-ao`、`pick-bo`、`pick-co` 各选一条边，`righto` 过滤，四个接起来与第一节的循环交出同样的列表，代码文件里核对过。）
