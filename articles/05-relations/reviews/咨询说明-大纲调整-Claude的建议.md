## 卡住的地方怎么接

1. **收拢是摊开的逆操作。** 第二节把 `cache` 摊开成 `rows`，得到关系。反过来，把关系按输入收拢，就是一个交出列表的函数。`right-triangles` 本身就是 R 的这种表示，开篇做的事在这里被认出来。
2. **接着问：这样的函数怎么拼。** 伪代码里的关系是由小关系并列拼出来的。交出列表的函数用普通的复合接不上，因为后一个函数吃的是一个元素，前一个交出的却是一张列表，得用 `append-map`。
3. **拼出来的正是 `for*/list`。** 把三角形问题写成这种拼接，得到的就是第一节的三层循环。由此进入 `for*/list` 与 `let*` 的对比。

Noah 22:49 的补充（伪代码里的一条链 `(≤ l a b c h)`，开头的循环分三步算，所以开头就是关系的复合）与上面第 2、3 点是同一件事，而且更具体。Claude 的补充：要把三步接起来，每一步得把后面用得着的东西带上，也就是 `(l h)` → `(a h)` → `(a b h)` → `(a b c)`，再加第四步用 `pyth?` 过滤；数学上的链没有先后，是计算选了「先 a、再 b、再 c」这个顺序，方向就是从这里进来的。

## 三个难点和处理

1. **方向。** 函数表示的关系分输入和输出，伪代码里的关系不分。解法：把目标看作代换之间的二元关系，也就是 `Substitution → Substitution`，输入是「目前知道多少」，输出是「现在知道多少」；合一负责双向匹配。这兑现了 03 那句「参数可以是还不知道的数」，也让「有了 amb，任意函数都是二元关系」直接用上：目标就是 ℛ 里的一个普通函数，并列就是函数复合。
2. **三角形问题本身不需要合一。** 到 06，amb 版已经把它解出来了。合一的动机得来自伪代码的写法：`run*` 先声明 a、b、c 未知，再陈述条件；要照原样跑它，就得有未知项。这一点 Claude 最没把握；不够的话，在 07 加一个只有合一才做得到的小例子。
3. **𝒮、ℒ、ℛ 的联系。** 用一张三行的表，只摆事实：各自的箭头是什么，怎么复合，每个输入占几行。再加两句：`collect` 把 ℛ 的函数变成 ℒ 的，`choose` 反过来。不用范畴论的词，不提前说第六篇的名字。

## 基于 `demo.rkt` 时已经验证过的两处差异

- `demo.rkt` 的 `run*` 只接受一个查询变量，`(run* (a b c) …)` 展开不了。要么把 `run` 扩成多个变量（TRS 第二版与 faster-miniKanren 的写法），要么写成 `(run* (t) (fresh (a b c) (== t (list a b c)) …))`；后者原样可跑，交出同样的六组，但 03 就得先讲 `fresh` 和 `==`。
- `≤` 与 `pytho` 要读出已确定的值，官方的办法是 `project`；它在 ambKanren 的 `main.rkt` 里，`demo.rkt` 没有。
