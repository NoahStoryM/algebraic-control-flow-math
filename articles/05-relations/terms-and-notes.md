# 用词与笔记

这一页是第五篇自己的规矩与底稿：用词、核对过的事实、不进正文的笔记。全系列共用的写法在总纲的「叙事指南」。

## 这一篇的用词

| 词 | 规则 |
| --- | --- |
| 表、列表 | 「表」是数学对象，行的集合，没有先后与重复，可以有无穷多行；「列表」是 Racket 的值，程序每次交出的是列表 |
| 函数的表、关系的表 | 前者每个输入恰好占一行，后者同一个输入占零行或多行。全篇只有这两种表 |
| 关系、目标 | 关系语言描述的是项之间的「关系」；实现里环境之间的二元关系叫「目标」。两层不混用 |
| 环境 | 这一篇没有合一，目标之间传的是「环境」，不叫「代换」；最后点合一时可以带一句，加上合一它就成了代换 |
| 时间线、回溯 | 04 才出现，之前不谈 |
| `amb` | 正文里一律用代码体；失败写 `(amb)`；`fail`、`collect` 不再出现；`choose/k`、`choose` 只作推导里的名字；不提 amb 库 |
| 上标 ᵒ | 关系名的后缀，照《The Reasoned Schemer》；相等若用到写 `≡` |
| 不出现的词 | 单子、Kleisli、do 语法；构造逻辑、关系代数、关系演算、连接、投影、范式、函数依赖 |
| 可以用的词 | 笛卡尔积、零元关系、一元关系、键 |

- 加粗并给过英文的术语，以正文为准：关系、N 元关系、二元关系、谓词（02），不确定计算、不确定运算符（06）。00 的「搜索树」与 01 的「表」不补英文（Noah 10/4）。
- 本篇只讨论有限的搜索，即整个搜索过程能够完成。
- 不承诺实现做不到的事：没有合一，关系只朝一个方向查，条件的先后不能反。

## 核对过的事实

这些都用代码跑过，写正文时可以直接用。

- `choose` 与 `list->amb` 是同一个函数（08 的练习）。
- `∘ℒ` 的化简每一行都相等；绕道 ℬ 的定义与 `(foldr append-map (list x) f*)` 在零步、一步、四步时一致。
- 08 末尾的两行并排成立；把 ℒ 的箭头搬到 ℬ，第一行收回来就是第二行。
- 09 的程序在暂定的内核里原样运行：边界 1 到 20 得到六组，许多边界下与 `amb` 版逐组相同；条件写反了次序会报「还没有确定」。
- `function->relation` 保持复合与恒等；`∘ᵒ` 的单位是 `(function->relation values)`。
- 把列表换成流只要改四个词，得到的是惰性但仍然深度优先的搜索。
- 把 ambKanren 的 `demo.rkt` 换成这一篇的定义去跑《The Reasoned Schemer》的 171 条测试：141 条通过，0 条结果不符，30 条停不下来，全是对有无穷多答案的关系取前几个。换成二十来行的惰性版全部通过。

## Astra 的限定

10/4 Astra 核对「目标是二元关系」时加的限定，正文必须守住。当时说的是代换，这一篇现在说环境。

1. 分清三层：目标交出的原始环境，从环境读出的查询答案，答案表示的数学解集。「相同」「可交换」在三层上不是同一个断言。
2. 可用的点题句：在这个实现里，忽略结果的顺序和重复，一个目标可以看作环境之间的二元关系，它把一个输入环境关联到零个或多个成功的输出环境。不说「这就是 miniKanren 的全部本质」。
3. 有了 `amb`，普通的复合就是关系的复合，这依赖 `in-amb` 的边界，限于纯的、有限的搜索。使用 `amb` 的过程不再是数学上的函数。
4. 合取在环境的关系上是复合，在解集上是交集。
5. 「只增不改」推不出可交换。能说的只是：纯关系式的目标、搜索完整终止时，交换合取两侧不改变解集。
6. 07 的元组不是「小的环境」：元组会丢信息，`(l h)` 到 `(a h)` 丢了 `l`。
7. 保留顺序和重复只对本文的 `amb` 与有限列表成立；流上的 `bind` 与 `∘ℒ` 不是同一个函数。

Claude 说错过的三处，别再犯：「只增不改所以可交换」不成立；「合一只是确定两头的东西」说轻了；「元组是小的环境」只是比喻。
