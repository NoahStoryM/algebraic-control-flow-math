# 第一步：独立作答

## 整体判断

这两节回答的是作者心里的问题：怎样从 𝒰 落回 𝒟，怎样凑齐四个世界。读者读到这里，心里的问题有两个，而这两节都没有正面接住：

1. 在 𝒦 里写程序，延续还得一个个手写，怎么办？
2. 这一大套东西，离开 `call/cc` 还剩下什么？

另外有一个结构上的事实，正文没有用上：**宏为每个绑定造出的 `(∘𝒦 cps:kv id)`，类型是 `(→𝒦 (¬¬ a) b)`，展开就是 ¬¬a → ¬¬b。它本身就是一支 𝒟 的箭头，并且恰好等于 `((∘ neg flip) cps:kv)`。** 也就是说，「落回 𝒟」并不是一个需要另外动机的操作，它就是绑定本身在做的事。

所以我的核心建议是先造后认：先造宏（再次隐藏延续、嵌入语言），再在宏里认出「落回」，最后给整件事起名叫否定翻译。`neg²` 留作纯函数这一特例，签名改成 𝒟 → 𝒟。

## 1. 动机：读者此刻的问题是什么

读完「两个 call/cc」，读者手里有三样东西：𝒦 的复合、𝒦 ≅ 𝒞、一个纯 λ 写成的 `cps:call/cc`。第一篇的问题是「构造性语言怎么支持经典推理」。到这里，读者自然会问：

> 那么，一段用了 `call/cc` 的程序，能不能整段改写成不用 `call/cc` 的程序？改写以后，类型和接法变成什么样？

「落回 𝒟」和「否定翻译」应该回答的就是这一个问题，答案分三层：

- **能改写。** 证据就是宏加 `cps:call/cc`，嵌入语言的 `mul` 和阴阳谜题都跑通了。
- **改写的产物落在 𝒟。** 每个绑定都是一支 ¬¬a → ¬¬b 的纯函数，并且在这里，宿主自己的 `∘` 就能把它们接起来。
- **代价。** 每个类型裹上 ¬¬；启动时要从外面借一个终结延续。这正好接上结论。

现在的写法把问题换成了「𝒰 的箭头能不能算 𝒟 的箭头」。读者不知道为什么要这样问，于是 `←`、`⨾`、`neg` 的第二种读法、四世界表格、四世界图连着登场，全都没有着落。还有一处容易被忽略：𝒦 的箭头 p → ¬¬q 本来就是 𝒟 里的函数类型。读者很可能会问「那为什么不直接算 𝒟 的箭头」，正文没有回答。真正的回答是：它们在 𝒟 里用 `∘` 接不上，两端差一层 ¬¬；落回以后才接得上。

## 2. 不说「函子」，怎样介绍 neg² 及它与 cps、anf:let* 的关系

我会换个次序：先认出「落回」，`neg²` 作为它的特例出现。三条关系都是【推导】，也都跑过：

```racket
;; 宏里的一个绑定，就是把剩下的程序落到 𝒟
(anf:eval ((∘𝒦 cps:kv id*) (cps:+ 1 2)))  ; 9
(anf:eval ((ext cps:kv)    (cps:+ 1 2)))  ; 9     ext = (∘ neg flip)

;; 纯的一步落下来，就是 neg²：(∘ ext cps) = (∘ neg flip flip neg) = (∘ neg neg)
(anf:eval ((neg² add1)      (cps:+ 1 2)))  ; 4
(anf:eval ((ext (cps add1)) (cps:+ 1 2)))  ; 4

;; cps 拆成「先包起来，再在包里做」：(cps f) = (∘ (neg² f) cps:id)
(anf:eval ((∘ (neg² add1) cps:id) 5))      ; 6
```

介绍 `neg²` 时，可以只说两件读者看得见的事：

- 「它把 p → q 搬成 ¬¬p → ¬¬q：交来的是一段还没跑的计算，它把 f 接在这段计算的结果后面。」
- 「搬过去的箭头照原样接得上：`(neg² (∘ g f))` 与 `(∘ (neg² g) (neg² f))` 相同，`(neg² id)` 就是 `id`。」

这两条都用了「复合」「恒等」，没用「函子」。正文现在的类型说明（$(¬q → ¬p) → (¬¬p → ¬¬q)$ 是直觉主义定理）可以保留。

三者的分工可以说成一张小表，不用新术语：

| 写法 | 做什么 |
|---|---|
| `cps:id` | 把一个值包成还没跑的计算 |
| `(neg² f)` | 在包里对结果做一步纯计算 |
| `((∘ neg flip) cps:k)`，也就是宏里的 `(∘𝒦 cps:k id)` | 在包里接一步可能跳走的计算 |

`cps` 是第一行接第二行，`anf:let` 是第三行。

## 3. 纯宿主里 ¬¬a → ¬¬b 能做什么、不能做什么

先说**命题层面**【推导】：$(p → ¬¬q)$ 与 $(¬¬p → ¬¬q)$ 在直觉主义逻辑里互相可推。一个方向是落回 `(∘ neg flip)`，另一个方向是接上 `cps:id`。所以单看逻辑，两者没有差别。

**程序层面**两者不一样，而且 ¬¬a → ¬¬b 更多：

- 来回一趟：先落回，再接 `cps:id`，回到原来的 𝒦 箭头。这是单位律 $f^* ∘ η = f$【定理：Kleisli 三元组的律，Moggi 1991 Def 1.2，记忆】。
- 反方向不行。下面两个纯函数都不是任何 𝒦 箭头落回的结果：

```racket
(define ((discard kka) kb) (kb 0))                          ; 不管交来的计算
(define ((twice kka) kb) (kka (λ (a1) (kka (λ (a2) (kb (+ a1 a2)))))))  ; 跑两次

;; discard 把交来的计算里的跳转丢了；先 discard 再接 cps:id 得到的 𝒦 箭头，落回后保留了跳转
(anf:eval (anf:let/cc ret (discard (ret 'escaped))))                          ; 0
(anf:eval (anf:let/cc ret ((ext (∘ discard cps:id)) (ret 'escaped))))  ; 'escaped

;; twice 把前面的工作做两次：输出 "xx" 对 "x"，答案都是 2
```

精确的说法是：落回给出的，恰好是那些「让交来的计算原样发生一次」的函数。用术语说，就是自由代数之间的同态，Kleisli 箭头与它们一一对应【定理：Mac Lane, CWM 第 VI 章 §5 的比较函子，记忆，未核页码】。¬¬a → ¬¬b 中其余的函数会丢弃、重复或改写交来的计算，它们在 𝒞 里没有对应的程序。

这样就回答了作者的直觉：

- **Kleisli 箭头**负责写程序的「一步」：手里有一个值，下一步做什么。
- **¬¬a → ¬¬b**负责「接」：不管中间做什么，宿主的 `∘` 都能接。`(∘𝒦 g f)` 等于 `(∘ (ext g) f)`，并且 `(ext (∘𝒦 g f))` 等于 `(∘ (ext g) (ext f))`，带跳转的箭头也成立，我实测过。
- **不能做**：不能从值开始（要先用 `cps:id` 包起来）；不能自己结束（要借终结延续）；把它当编程世界，会写出 𝒞 里没有的东西。

那些「多出来的」函数也不是废物。第三篇的 `reset`（λk. k(m id)）就不是同态：交来的计算若跳走，`ext` 会让跳转继续往外走，`reset` 却把它接住【推导】。这是处理边界的地方。但第二篇不能提，按约定不引用后文。

**一个前提要说明**【推导】：如果在 Set 里把 ⊥ 当成真正的空集，非空 a 的 ¬¬a 只有一个元素，上面这些区别全部消失。区别只在运行意义下（`a->⊥` 借自 `raise`），或答案换成一般类型 R 时成立。

## 4. 「否定翻译」落在哪里

| 东西 | 签名或身份 | 处理 |
|---|---|---|
| `neg²` | `(→𝒟 p q) → (→𝒟 (¬¬ p) (¬¬ q))` | 改成 𝒟 → 𝒟。它在运行时原样调用 f，所以输入是什么就只能保证什么。step1.rkt 第 8 节实测：交给它一支用了宿主 `call/cc` 的函数，包出来的仍然调用宿主 `call/cc` |
| `call/cc` 的翻译 | `cps:call/cc` | 翻译规则里唯一一条不平凡的规则 |
| 整段程序的翻译 | `anf:` 宏，加上 `cps` 提升原语 | 「否定翻译」这个名字落在这里 |

𝒞 → 𝒟 这个方向，在运行时**没有**对应的函数：程序一旦写成 𝒞 的函数值，内部用了什么就看不见了。要搬的是程序文本，所以它只能是宏。这一点正好接上第一篇的线索：第一篇是用纯 λ **重写**阴阳谜题，重写对象是程序，不是函数。

类型对应可以写成：一段类型为 a 的程序变成 ¬¬a；一个函数变成 𝒦 箭头 a → ¬¬b；所有改写的零件都在 𝒟。

逻辑上的对应：经典定理的否定翻译是直觉主义定理【定理：Gödel 1933、Gentzen 1936、Kolmogorov 1925、Kuroda 1951，记忆】。按值 CPS 对应 Kuroda 的版本【Murthy 1990，记忆】。`call/cc` 的类型是 DNE【Griffin 1990，记忆】。

还有一处措辞要改：「第一层（neg）把延续变成参数，这是全部经典能力的来源」。对纯 f 来说，`(neg² f)` 里没有任何经典能力；经典能力在 `cps:call/cc` 这类箭头落回的结果里。

## 5. 「两个 call/cc」的推理

「同构，所以也该有 call/cc」有两个漏洞：

- **同构比较的是两端固定时的箭头。** 它没有说 `call/cc` 类型里的 ¬p → p 这个**对象**在 𝒦 里对应什么。照搬会得到 `(cps call/cc)`，类型是 (¬p → p) →𝒦 p，而不是 (¬𝒦p →𝒦 p) →𝒦 p【推导】。
- **就算照搬成功，也推不出「纯」。** 经 `cps` 和 `uncps` 搬过去的 `call/cc` 内部仍然调用宿主的 `call/cc`。纯 λ 写成的版本存在，是另外一个事实。

建议把同构变成问题，而不是前提：

> 同构说明 𝒦 和 𝒞 一样强，可证明里借了 `call/cc`。𝒦 这份力量是借来的，还是它自己的？拿最经典的 Clavius 律试试：写成 𝒦 的箭头，展开别名，得到 ((p → ¬¬⊥) → ¬¬p) → ¬¬p。这是一条直觉主义定理。

既然是直觉主义定理，就应该能用纯 λ 写出来，于是写出 `cps:call/cc`。这一步是【推导】，`cps:call/cc` 这段代码本身就是证明。

两点补充：

- `neg:call/cc` 降为练习。后文没有用到它，留在正文只会加重最难读的那一段。
- 「`kp` 提升一份交出去，留一份自己用」这个观察值得留在正文。

## 6. 顺序与图表

建议的顺序：

三种箭头 → 经典与构造（只保留 𝒞/𝒰/𝒦 三角图和 `unneg`）→ 𝒦 自己的 call/cc → 再次隐藏延续 → 嵌入语言 → 计算的位置 → **落回 𝒟**（新写）→ **否定翻译**（命名）→ 结论

新的「落回 𝒟」按这个次序展开：

1. 嵌入语言里一次 `call/cc` 也没用；把宿主分成 𝒞 和 𝒟。
2. 宏造出的 `cps:kkkv` 两端都是 ¬¬，它就是 𝒟 的箭头。
3. 拆开它：`flip` 一下得到 ¬b → ¬a，这是方向相反的普通函数。`←` 和 `⨾` 在这里引入，这才是「方向第一次造成障碍」的地方，`∘𝒰 = ⨾` 也在这里认出。再 `neg` 一次，方向就正了。
4. 纯的一步落下来就是 `neg²`。
5. 落下来以后用 `∘` 就能接。
6. 反方向只能取回一部分。

## 你们漏掉的

1. **用落回消解「两个 id」的混淆。** #78 和 Astra 都靠就地展开类型来区分宏里的 `id` 与 `cps:id`。一旦认出 `(∘𝒦 cps:kv id) = ((∘ neg flip) cps:kv)`，宏里的 `id` 只是「用 `∘𝒦` 表达落回」的技巧。#78 里的「连接等式」`((∘𝒦 cps:kv id) (cps:g y)) = ((∘𝒦 cps:kv cps:g) y)`，也就成了「`∘𝒦` 落下来是 `∘`」的前一半。乙在前面埋下，落回一节收获。宏本身仍保留 `∘𝒦` 加 `id` 的形状，与第六篇的通用 `let*𝒦` 一致。
2. **命题等价、程序不等价。** p → ¬¬q 与 ¬¬p → ¬¬q 在逻辑上互推，在程序上后者更多。这是不用范畴论就能说清「前者取代不了后者」的说法，你们的记录里没有。另附 `discard`、`twice` 两个续延版的反例，你们只跑过列表和异常的版本。
3. **四世界图里有不交换的环**（见上面第 6 问）。
4. **「全部经典能力的来源」这句的错误**，以及那处「后面的 `cps:display`」违反约定。
5. **10/16 试验之二的结论说过头了。** `neg²:lift`（多参数）、`neg²:if`、`neg²:app`、`neg²:let/cc` 里面都已经含着落回。比如 `neg²:if` 就是 `ext (λ (b) (if b kk1 kk2))`；多参数的 lift 要先后运行几段计算，单靠 `neg²` 做不到。所以「四样工具只差一个按值绑定」并不准确：按名的那门语言在每个原语里都用了落回，差别只在 `let` 绑定的是计算还是值。
