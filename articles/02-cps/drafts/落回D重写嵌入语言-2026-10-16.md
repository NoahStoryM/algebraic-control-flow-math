# 第二篇试验：用宿主的 `let*` 与 `neg²:` 重写「嵌入语言」的例子（2026-10-16）

Noah 10/16 要的试验：把第二篇「嵌入语言」的几个例子改用宿主 `let*` 与 `neg²:` 箭头写，看代码和运行行为，供他想叙事。只是材料，不是正文稿。

代码与全部运行结果：`articles/02-cps/checks/d-side-rewrite-1016.rkt`（依赖同级目录下的文章仓库，底本 `dev`；Racket 8.10，全部 check 通过）。

## 工具

分两档，看各自能写到哪里。

- **第一档**：只用 `neg²`（把纯函数搬成 ¬¬p → ¬¬q）、`cps:id`、Noah 的 `neg²:call/cc`，加宿主的 `let*`。
- **第二档**：再加「落回」`(neg (flip h))`，把一支 𝒦 箭头 h : p → ¬¬q 变成 ¬¬p → ¬¬q。按旧的命名约定，h 落回以后记作 `neg²:h`；对纯函数 f，`neg²:f` 就是 `(neg² f)`（实测）。

```racket
(define (落回 h) (neg (flip h)))

;; Noah 10/16 的定义；类型里 proc 的返回改成 ¬¬a
;; (: neg²:call/cc (∀ (a) (→ (¬¬ (→ (¬¬ (→ (¬¬ a) (¬¬ ⊥))) (¬¬ a))) (¬¬ a))))
(define ((neg²:call/cc kkneg²:proc) ka)
  (kkneg²:proc (λ (neg²:proc) ((neg²:proc (cps:id (neg² ka))) ka))))
```

## 结果一览

| 例子 | 第一档 | 第二档 |
| --- | --- | --- |
| (1 + 2) × 3 | 能写，得 9 | 不需要 |
| `mul` 遇零跳出 | 正常路径能写；跳出那一步多出一层 ¬¬，运行时报错 | 能写，结果与原文一致；跳出时后面的乘法没有执行 |
| 阴阳谜题 | 写不出：连「先运行这段、再运行那段」都做不到 | 能写，输出前缀与原文一致；每个结果的名字只能在 λ 里起 |
| 名字用两次 | 运行两次（`"!!"`） | （`anf:let*` 只运行一次，`"!"`） |

## 例一：(1 + 2) × 3

```racket
(let* ([kkv ((neg² +) (cps:id 1 2))]
       [kkw ((neg² (λ (v) (* v 3))) kkv)])
  kkw)
```

结果 9，与原文一致。`let*` 绑定的 `kkv`、`kkw` 是编码好的计算，不是数；`3` 只能写进纯函数里，`v` 这个名字也只能在 λ 里起。

## 例二：`mul`，遇零跳出

列表留在宿主里，分支用宿主的 `if`，正常路径的乘法用 `neg²`：

```racket
(neg²:call/cc
 (cps:id
  (λ (kkesc)                                   ; kkesc : ¬¬(¬¬a → ¬¬⊥)
    (let loop ([r* r*])
      (cond [(null? r*) (cps:id 1)]
            [(zero? (car r*))
             (define (g esc) ((neg² absurd) (esc (cps:id 0))))   ; g : (¬¬a → ¬¬⊥) → ¬¬a
             ((落回 g) kkesc)]                  ; 第一档写成 ((neg² g) kkesc)
            [else
             (define r (car r*))
             ((neg² (λ (res) (* res r))) (loop (cdr r*)))])))))
```

- **第一档**：跳出那一步要用 `kkesc` 里面的 `esc`。`g` 收到 `esc` 交出 ¬¬a，它本身是一支 𝒦 箭头；用 `neg²` 搬它，得到 ¬¬¬¬a，多一层。运行时这多出来的一层被当作数交给了乘法：`*: contract violation, expected: number?, given: #<procedure>`。
- **第二档**：把 `(neg² g)` 换成 `(落回 g)`，多的那层就没有了。`'(1 2 0 3 4)`、`'(1 2 3 4)`、`'()` 三个输入，结果与原文一致（0、24、1）。在乘法里打印：遇零时什么都没打印，不遇零时打印 `*3 *2 *1`，即跳出时后面的乘法确实没有执行。

## 例三：阴阳谜题

- **只用 `neg²` 写不出。** `neg²` 只能改一段计算的结果，做不到「先运行这一段，再运行那一段」，更做不到让后一段依赖前一段的结果。
- **照字面用宿主 `let*` 给四段计算起名字**（`kkyin`、`kk@`、`kkyang`、`kk*`），先后靠落回接，最后那一步 `(cps:yin cps:yang)` 要的是两段计算的结果，写不出来，只能丢掉。输出 `"@*done"`：四段各跑一次，没有阶梯。
- **第二档**：每一步用落回接，结果的名字在 λ 里起：

  ```racket
  ((落回 (λ (cps:yin)
           ((落回 (λ (_)
                    ((落回 (λ (cps:yang)
                             ((落回 (λ (_) (cps:yin cps:yang)))
                              (cps:display #\*))))
                     (cps:label))))
            (cps:display #\@))))
   (cps:label))
  ```

  输出前缀 `@*@**@***@****@*****@` 与原文一致。这正是 `anf:let*` 展开后的样子：一个绑定就是一次「落回作用在函数体的 λ 上」。

## 附：名字用两次

```racket
(anf:let* ([v (cps:say1)]) (cps:+ v v))                  ; 打印 "!"
(let* ([kkv (cps:say1)]) ((neg² +) (pair2 kkv kkv)))     ; 打印 "!!"
```

`cps:say1` 打印一个 `!` 再交出 1。`anf:let*` 绑定的是结果，`say1` 只运行一次；宿主 `let*` 绑定的是计算，用两次就运行两次。

## 读出来的东西（Claude 的观察，供 Noah 想叙事）

1. 第一档（`neg²` 加宿主 `let*`）能做的，只有「改一段计算的结果」：纯函数一路搬下去。一旦后一步要做的事取决于前一步的结果（跳出、分支、阴阳谜题），就多出一层 ¬¬，宿主的 `∘` 和 `let*` 压不回去。
2. 压回去的办法是落回，它就是 `anf:let*` 每个绑定在做的事。所以「不用新语法、留在宿主」走到底，得到的就是手写的 `anf:let*` 展开式。
3. Noah 的 `neg²:call/cc` 在第二档里可以正常使用，行为与 `cps:call/cc` 一致。它的类型是 Clavius 律的 Kolmogorov 翻译（外面少一层 ¬¬）。
4. 落回与 `neg²` 的关系：对纯函数，落回 `(cps f)` 就是 `(neg² f)`；先在 𝒦 里接再落回，等于先落回再用 `∘` 接（都已实测）。

# 试验之二：`let*` + `neg²:let/cc` + `neg²:if` + `neg²:` 逐字对照（10/16 晚）

Noah 的问题：能不能直接用这四样表达 `anf:let*` + `anf:let/cc` + `anf:if` + `cps:` 写的程序。代码：`articles/02-cps/checks/cbn-rewrite-1016.rkt`（Racket 8.10，全部通过）。

## 工具

```racket
;; Noah 的骨架补上 ka 那一层，再化简：neg²:call/cc 交进来的总是 (cps:id (neg² ka))
(define-syntax-rule (neg²:let/cc neg²:k b* ...)
  (λ (ka) (let ([neg²:k (neg² ka)]) ((let () b* ...) ka))))

;; 测试值是一段计算；两个分支本来就是还没运行的计算，不用宏
(define ((neg²:if kkb kk1 kk2) k) (kkb (λ (b) ((if b kk1 kk2) k))))

;; 另外要补两样：
;; 多参数的 neg²:f，收几段计算，从左到右运行，再交给 f
(define ((neg²:lift f) . kk*) ...)
;; 先后：宿主的 begin 会把前面那段计算直接丢掉，不运行
(define ((neg²:begin kk . kk*) k) ...)
;; 调用一段交出函数的计算（阴阳谜题的 (yin yang)）
(define ((neg²:app kkf . kkx*) k) (kkf (λ (f) ((apply f kkx*) k))))
```

## `mul` 逐字对照

```racket
(neg²:let/cc neg²:return
  (define (neg²:loop kkr*)
    (neg²:if (neg²:null? kkr*) (neg²:*)
             (let* ([kkr (neg²:car kkr*)])
               (neg²:if (neg²:zero? kkr) (neg²:return kkr)
                        (let* ([kkr* (neg²:cdr kkr*)]
                               [kkres (λ (k) ((neg²:loop kkr*) k))])   ; 递归调用要延迟
                          (neg²:* kkres kkr))))))
  (neg²:loop (cps:id r*)))
```

与原文逐行对应：`anf:let*` → `let*`，`anf:if` → `neg²:if`，`anf:let/cc` → `neg²:let/cc`，`cps:f` → `neg²:f`，名字前缀 `kk`。三个输入结果与原文一致（0、24、1）。(1 + 2) × 3 也一致（9）。

唯一不能照抄的是递归调用：`(neg²:loop kkr*)` 写在 `let*` 的绑定里，宿主会立刻调用它；它又立刻调用下一层，没有终点（实测被系统杀掉）。原文里递归调用在延续里，要等前面的测试走完才发生。这里要写成 `(λ (k) ((neg²:loop kkr*) k))`，把调用推迟到真正运行时。

## 行为上的差别

| | 原文（`anf:`） | 四样工具 | 四样加一个按值绑定 |
| --- | --- | --- | --- |
| `mul` | 0 / 24 / 1 | 相同 | 相同 |
| 名字用两次（`say1` 打印 `!`） | `"!"` | `"!!"` | `"!"` |
| 阴阳谜题 | `@*@**@***…` | `@*` 后不再输出 | `@*@**@***…` |

四样工具组成的是一门**按名调用**的语言：`let*` 绑定的是计算，名字用几次就运行几次；`neg²:if` 的分支本身就延迟着；递归要手动延迟。`mul` 的名字指的都是纯的计算（`car`、`cdr`、`zero?`），重复运行看不出差别，所以结果一致。阴阳谜题依赖「`label` 只运行一次、捕获那一刻的延续」，按名调用时 `yin` 在 `(yin yang)` 处才运行，捕获的是那里的延续，行为就变了。

## 补上的那一样：按值绑定

```racket
(define-syntax-rule (neg²:let1 ([kkv e]) b* ...)
  ((neg (flip (λ (v) (let ([kkv (cps:id v)]) b* ...)))) e))
```

先把 `e` 运行一次，拿到结果 `v`，名字绑定到「交出 `v` 的计算」。阴阳谜题的两个绑定换成它，阶梯回来了；`say1` 只打印一次。它就是落回作用在函数体的 λ 上，即 `anf:let*` 每个绑定在做的事。

## 读出来的东西（Claude 的观察）

1. 四样工具能表达的，是同一批程序的按名调用版本；要表达 `anf:` 程序（按值调用）的行为，恰好还差一样：按值绑定，也就是落回。
2. 按名调用这一侧，类型是每个箭头 ¬¬A → ¬¬B（Kolmogorov 的形状）；按值调用这一侧是每个箭头 A → ¬¬B（`cps:`、𝒦）。第二篇注意框里「按值调用对应 Kuroda，按名调用对应 Kolmogorov」在这里有了可运行的对照（对应关系本身凭记忆，引用前要核）。
3. 叙事上的一个可能：落回 𝒟、否定翻译那一节，可以落在「同一个程序的两种嵌入：按名与按值」上；`anf:let*` 的必要性，就是按值调用的必要性。
