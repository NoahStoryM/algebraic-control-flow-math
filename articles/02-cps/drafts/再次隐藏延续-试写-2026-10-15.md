## 甲：「三种箭头」末尾新增

`∘𝒦` 是一种复合。宿主的复合有两条用惯了的性质。一是恒等函数接在哪一头都不改变什么：`(∘ f id)` 和 `(∘ id f)` 都是 `f`。二是三个函数接在一起，先接哪两个都一样，`(∘ h (∘ g f))` 与 `(∘ (∘ h g) f)` 相同，所以可以直接写成 `(∘ h g f)`。`∘𝒦` 也写成了能收任意多支箭头的样子，这两条它有没有？

先找 𝒦 的恒等。它得是一支 $q →_𝒦 q$ 的箭头，什么工作都不加：收到 `x` 和延续 `k`，把 `x` 原样交给 `k`。这正是 `cps` 作用在宿主的 `id` 上得到的：

```racket
(: cps:id (∀ (q) (→𝒦 q q)))
(define cps:id (cps id))
```

`((cps:id x) k)` 就是 `(k x)`。把它接在 `cps:f` 的两头，照上面 `∘𝒦` 的展开各算一遍：

```racket
  (((∘𝒦 cps:id cps:f) x) k)
= ((cps:f x) (λ (y) ((cps:id y) k)))
= ((cps:f x) (λ (y) (k y)))
= ((cps:f x) k)

  (((∘𝒦 cps:f cps:id) x) k)
= ((cps:id x) (λ (y) ((cps:f y) k)))
= ((λ (y) ((cps:f y) k)) x)
= ((cps:f x) k)
```

接在后面，`cps:id` 收到 `y` 只是转交给 `k`，这一层 λ 可以拿掉；接在前面，它把 `x` 原样交给等着的 λ。两边都回到 `cps:f` 自己。

再看三支箭头。两种括号各展开一遍：

```racket
  (((∘𝒦 cps:h (∘𝒦 cps:g cps:f)) x) k)
= (((∘𝒦 cps:g cps:f) x) (λ (z) ((cps:h z) k)))
= ((cps:f x) (λ (y) ((cps:g y) (λ (z) ((cps:h z) k)))))

  (((∘𝒦 (∘𝒦 cps:h cps:g) cps:f) x) k)
= ((cps:f x) (λ (y) (((∘𝒦 cps:h cps:g) y) k)))
= ((cps:f x) (λ (y) ((cps:g y) (λ (z) ((cps:h z) k)))))
```

最后一行相同：`cps:f` 的延续里等着 `cps:g`，`cps:g` 的延续里等着 `cps:h`，最后才是 `k`。括号只决定先把哪两支接起来，接成的延续链是同一条；不分括号的 `(∘𝒦 cps:h cps:g cps:f)` 展开也是这一条。

这两条性质各有名字。恒等接在哪一头都不起作用，叫**单位律**，`cps:id` 是 `∘𝒦` 的单位；先接哪两支都一样，叫**结合律**。有了它们，𝒦 的箭头可以像宿主的函数一样连接、拆开、消去空步骤，不必每次把延续一层层展开来核对。

系列标题里的「代数」，说的就是这种情形：控制流有了自己的复合，复合满足单位律和结合律，对程序的推理可以按等式进行。

## 乙：「再次隐藏延续」重写

# 再次隐藏延续

回想开头的观察。`let` 脱糖为 lambda 调用，延续藏在 `let` 里面：等待结果的那个 λ 不用我们写，绑定的语法替我们写了。CPS 变换把延续拉出来变成显式参数，这个 λ 就得亲手写。能不能反过来：用 `let` 语法把 CPS 的延续再藏回去？

先看一个具体例子。假设我们有 CPS 提升的加法 `cps:+` 和乘法 `cps:*`，想计算 `(1 + 2) × 3`：

```racket
(anf:let ([v (cps:+ 1 2)])
  (cps:* v 3))
```

照 `let` 的办法，函数体包成 `(λ (v) (cps:* v 3))`，再用在 `(cps:+ 1 2)` 上。可是用不上去：这个 λ 要的是一个数，`(cps:+ 1 2)` 交出的却是 $¬¬\text{Nat}$。

先不管怎么写，看接上以后要发生什么。把 `(cps:+ 1 2)` 算出的值记作 `kkv`，它还在等延续。整段程序收到最终的延续 `k` 时，应当把一个延续交给 `kkv`：这个延续拿到 `v`，交给函数体，函数体的结果再交给 `k`：

```racket
(λ (k) (kkv (λ (v) ((cps:* v 3) k))))
```

这个形状在「三种箭头」里见过。`∘𝒦` 的展开是 `((cps:f x) (λ (y) ((cps:g y) k)))`：让 `cps:g` 是函数体那支箭头 `(λ (v) (cps:* v 3))`，再让 `(cps:f x)` 恰好是 `kkv`，两边就一模一样。

`(cps:f x)` 要等于 `kkv`，最省事的办法是让 `cps:f` 原样交出收到的东西，把 `kkv` 本身交给它。宿主的 `id` 正好做这件事。它在这里当一支 𝒦 的箭头用，类型写作 $¬¬\text{Nat} →_𝒦 \text{Nat}$，展开就是 $¬¬\text{Nat} → ¬¬\text{Nat}$：收进来的是整个编码好的值，交出去的还是它，并没有从 $¬¬\text{Nat}$ 里取出一个数。宏照这样展开：

```racket
(let ([kkv (cps:+ 1 2)])
  (: id       (→𝒦 (¬¬ Nat) Nat))
  (: cps:kv   (→𝒦     Nat  Nat))
  (: cps:kkkv (→𝒦 (¬¬ Nat) Nat))
  (define (id kkv) kkv)
  (define (cps:kv v) (cps:* v 3))
  (define cps:kkkv (∘𝒦 cps:kv id))
  (cps:kkkv kkv))
```

`cps:kkkv` 收下 `kkv`，再收到 `k`，照 `∘𝒦` 的展开算出来的，正是上面那个 λ 的函数体。

宏里的 `id` 和「三种箭头」里的 `cps:id` 不是一回事。`cps:id` 的类型是 $q →_𝒦 q$，收到一个普通的值，交给延续，是 `∘𝒦` 的单位。宏里的 `id` 收到的是已经编码好的 $¬¬\text{Nat}$，原样转交，作用是让这个现成的值接进箭头链。

宿主的 `let` 也能写成这样。把等着结果的 `(λ (v) b)` 记作 `kv`，`(let ([v e]) b)` 就是 `(kv e)`，前面多接一个 `id` 也不变。两边并排，只差在用哪个复合：

```racket
(let     ([v e]) b)  =  ((∘  kv     id) e)    ; kv     = (λ (v) b)
(anf:let ([v e]) b)  =  ((∘𝒦 cps:kv id) e)    ; cps:kv = (λ (v) b)
```

绑定的右边往往本身就是一次调用。这里的 `(cps:+ 1 2)`，是箭头 `cps:+` 作用在 `1`、`2` 上。宿主里，`(let ([v (+ 1 2)]) b)` 就是 `((∘ kv +) 1 2)`：`id` 可以拿掉，`kv` 直接接在 `+` 后面。𝒦 里交给同一个 `k`，两边也一样：

```racket
  (((∘𝒦 cps:kv id) (cps:+ 1 2)) k)
= ((cps:+ 1 2) (λ (v) ((cps:kv v) k)))
= (((∘𝒦 cps:kv cps:+) 1 2) k)
```

第一行照 `∘𝒦` 展开，`id` 原样交出 `(cps:+ 1 2)`；第二行再照 `∘𝒦` 倒着收回去。一般地，`id` 收下的若是 `(cps:g y)` 这样刚算出来的值，不如把后一步直接接在 `cps:g` 后面：

```racket
((∘𝒦 cps:kv id) (cps:g y))  =  ((∘𝒦 cps:kv cps:g) y)
```

这条等式和单位律不同：拿掉的不是 `cps:id`，而是宏为了接住现成的值临时放进去的 `id`。两边还有一处先后之差：左边先算出 `(cps:g y)`，右边要等收到 `k` 才调用 `cps:g`。两者相同，前提是 CPS 箭头收到参数时只造出一个等待延续的函数，不做别的事；`cps` 造出的箭头都是这样，下面也一直这样假定。

多个绑定的 `anf:let*` 是嵌套的单个绑定，和 `let*` 一样。开头看过宿主里两个绑定的展开，最后剩下 `((∘ g f) x)`。`anf:let*` 走的是同样几步，现在每一步都有一条等式做依据：

```racket
  (anf:let* ([y (cps:f x)]
             [z (cps:g y)])
    (cps:id z))
= ((∘𝒦 (λ (y) ((∘𝒦 (λ (z) (cps:id z)) id) (cps:g y)))
       id)
   (cps:f x))
= ((∘𝒦 (λ (y) ((∘𝒦 cps:id cps:g) y)) cps:f) x)
= ((∘𝒦 cps:g cps:f) x)
```

第一步照宏展开，把 `kky`、`kkz` 代回去。里外两层是同一个样子：`id` 收下一个刚算出来的值。

第二步用上面的等式拿掉两个 `id`，后一步直接接在 `cps:f`、`cps:g` 后面。`(λ (z) (cps:id z))` 只把 `z` 交给 `cps:id`，它就是 `cps:id`。

第三步用单位律：`cps:id` 接在 `cps:g` 后面不改变什么，里层只剩 `(λ (y) (cps:g y))`，也就是 `cps:g`。

三个绑定时，同样几步得到 `(∘𝒦 (∘𝒦 cps:h cps:g) cps:f)`：嵌套的绑定总是先把后面几步接起来。宿主里同样的 `let*` 得到 `(∘ h g f)`，不分括号；𝒦 这边靠结合律，括号也可以去掉，写成 `(∘𝒦 cps:h cps:g cps:f)`。

```racket
(let*     ([y     (f x)] [z     (g y)])         z)   =  ((∘      g     f) x)
(anf:let* ([y (cps:f x)] [z (cps:g y)]) (cps:id z))  =  ((∘𝒦 cps:g cps:f) x)
```

`let*` 是 `∘` 的另一种写法，`anf:let*` 是 `∘𝒦` 的另一种写法，多出来的是中间结果的名字。展开到底，手写 CPS 时的那个 λ 还在，只是不用我们写了。
