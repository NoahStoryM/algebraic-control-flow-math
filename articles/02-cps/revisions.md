# 修订记录

## 2026-10-06 的修订

起因是写第五篇 08 时的一个发现：第二篇也可以像第五篇那样一步步推。Noah 11:09 的话：第二篇这几块没讲透，正好补上，包括嵌入语言的宏展开后是什么、闭包链、计算的位置。

**定下来的约束**（Noah 11:15）：正文不出现范畴论术语；「计算的位置」是为后面栈的切片埋的伏笔，要在不用术语的前提下讲清楚。

**怎么改的**：修订稿在另一个对话里完成。第一版只插入、不动原文，读起来是拼接的，于是改为整体润色，允许删改原文。「计算的位置」第一稿太累，改成只讲一个意思的短版。16:57 发回这边核对，17:04 又润色了两句。

| 节 | 改了什么 |
| --- | --- |
| 求值顺序与 ANF | `let` 的脱糖从 `≡` 改成等式的 `=` |
| 否定的层次 | `cps` 与 `neg` 互相定义的代码块改成两行等式；新增 `neg` 接两次的化简；新增 `(fact/k 3 k)` 的闭包链 |
| 三种箭头 | 新增 `∘𝒦` 的七行展开，落到 `((cps:f x) (λ (y) ((cps:g y) k)))`，并与手写 `fib/k` 时的包法对上 |
| 否定翻译 | 先说 `neg²` 只翻译类型，由此引出 `cps->neg²`；新增换一个方向的四行化简与等式 `(∘𝒦 cps:g cps:f)  =  (∘ neg²:g cps:f)` |
| 再次隐藏延续 | 重写：动机改成「等着结果的那个 λ 由绑定的语法替我们写」；`let` 与 `anf:let*` 的脱糖并排；`let*` 与 `anf:let*` 两段化简；结论是两行并排 |
| 计算的位置 | 改短：加 `kp  =  ((neg f) kq)  =  (∘ kq f)`，运行时同一条等式换个读法 |

| 完整代码参考 | 没有变 |

**核对**：新增的每一段化简都用文末的代码逐行跑过，全部相等，包括用了 `cps:call/cc` 的箭头；`(fact/k 3 k)` 递归到底时手里的延续确实是 `(∘ k mul3 mul2 mul1)`。核对代码在附件里。

**核对时提出的四处与处理**：

1. 正文里没有引入 `∘` 的地方了。不补，第一篇说明过。
2. `(kp p)` 里 `p` 当值用。保留，按命名法 `kp` 收到的值就叫 `p`。
3. 「`fact/k` 每递归一层就这样接一次」改成「不带累积器的那版 `fact/k` 每递归一层就这样接一次」。
4. 「否定翻译」里补了半句：「只搬后一支就够了：`(cps->neg² cps:g)` 的类型是 ¬¬q → ¬¬r，补上的正是这一层，`cps:f` 交出的 ¬¬q 它直接收下。」

另有两处是断言而不是推导，留着没动，与系列不证这类性质的做法一致：`neg²:id` 什么也不做；`cps->neg²` 保持复合（测过，成立）。

**伏笔写到哪一步**：停在「相邻两个位置的延续只差中间一步」。「把出口换成中途的某个位置，截下来的一段自己又是带出口的世界」这一层没有写进第二篇，再往前就成了向后预告。这一层的说法是 Claude 的建议，不是 Noah 的话。
