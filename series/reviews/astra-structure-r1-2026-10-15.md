# Astra：第二、三篇的结构问题，第一轮（2026-10-15）

回答 Noah 09:17 的提示词：标题「代数」未兑现、第二篇「否定翻译」与「再次隐藏延续」、第三篇「局部否定下的世界」。原文照录。

我的整体判断是：这几处有共同病根，但不能只用一个编辑动作解决。第二、三篇的主线是“遇到一个编程问题，造出解决它的办法”；几处困难段落却突然改成“把已经出现的东西放进一张完整的对应表”。读者于是连续学习新记号，却不清楚它们解决了什么新问题。

与此同时，正文已经在做代数推演，却没有把真正有用的规律指出来。于是出现一个反差：体系介绍很多，代数承诺却迟迟没有兑现。

我建议保留系列现有的发现路线，调整两件事：让每次类型整理紧接一个需要它的问题；让单位律、结合律在第一次产生实际用途时就被认出来。neg²、逃逸的终点和 Peirce 律的范围，则需要实质修正，不能靠叙事淡化。

1. 哪些是同一个问题，哪些要分开处理

共同问题可以具体说成：正文过早追求表示之间的完整对应，过晚交付读者可以使用的规则。

第二篇尤其明显：

* “三种箭头”刚刚造出了 ∘𝒦，这是一个实质进展：以后不用亲手接每个延续。
* 随后进入往返、三世界关系、第四个世界、反向箭头、反向复合、第二种 neg、四世界总图。
* 等到“再次隐藏延续”，才回到读者原本关心的问题：怎样给中间结果起名字，怎样写程序。

这段距离太长。第三篇也类似：局部延续、丢弃、边界都已经通过代码建立，到了“局部否定下的世界”，又要求读者用三种签名和四个运算符重新建立一次对应。

但有三件事应当单列：

* 宏展开的六步推导是讲解粒度问题。即使没有世界图，它仍然会像调试日志，需要重新选择证明中间站。
* neg² 是身份混淆。运行时包装函数与翻译程序不是同一件事，必须分开。
* 整个程序出口、一般 Peirce 律是过强表述。这些需要收紧事实范围，不能仅仅移到注释。

所以，我不会把方案概括成“少讲数学”。应当少的是重复的表示整理；应当增加的是已经造出来的运算究竟允许怎样推演。

2. 各处怎样调整，尤其第二、三篇的分工

第二篇：把“造出翻译”与“认出否定翻译”重新接起来。

我建议采用下面这条主线：

接出 CPS 复合 → 找到其中的空步骤和复合规律 → 用显式延续实现控制 → 给中间结果命名 → 用宏组织一段程序 → 认出这里发生的翻译。

这需要拆分现有“否定翻译”一节，而不只是把两节整体交换。

具体安排如下。

现有内容	建议处理
neg、flip、∘𝒰，再推出 ∘𝒦	保留。这条构造路线有实际产出。
cps:id	从“再次隐藏延续”提前到 ∘𝒦 之后，作为“不增加工作的一步”造出来。
cps／uncps 往返	缩短主线篇幅；依赖条件的反方向论证移到后置推导。不再承担“所有表示全部等价，因此能力齐全”的主线证明。
编码中的 call/cc	保留，依据显式延续如何传递、如何处理当前延续直接说明。
“落回 𝒟”	保留纯实现与宿主能力的区别；删去此处对 ←、⨾ 的再次建制，以及对完整世界地图的追求。
“否定翻译”的任务说明	放在宏之前：仅包裹现成函数还不够，需要把程序内部的各步也组织成编码。
“否定翻译”的命名与总结	放在宏和一个完整例子之后。此时读者已经看到翻译怎样发生。
neg²	保留为短小的纯函数构造，退出“把任意经典程序送入纯宿主”的主线位置。

这里有一个必须同步处理的上游依赖：“两个 call/cc”目前借“与 𝒞 同构”推出编码拥有相应能力。若只改后面的“否定翻译”，这一段仍会把读者带回过强的理解。应改成：延续已经成为参数，因此可以直接构造相应操作。受条件限制的往返，是另一项结果。

两节的职责可以明确到下面这个程度：

* “再次隐藏延续”负责造。怎样把已经存在的 CPS 接法变成绑定、顺序和控制语法，让程序员不再手写延续。
* “否定翻译”负责认。回看刚刚造出的程序：结果怎样编码，控制操作怎样展开，哪些宿主能力因此不再需要，哪些原语仍然保留原来的效应。

这样，“否定翻译”不会先宣布一个尚未完成的工作；宏也不再像全文主要结论之后附赠的一套语法糖。

“再次隐藏延续”：先让读者看见接法，再解释那个 id。

目前入口是一个完整、带类型的实现展开，读者还没理解绑定需要什么，就先撞上：

id:\;¬¬a\to_{\mathcal K}a.

我建议只先看一个绑定。设 m 已经是算好的编码值，B(v) 是使用中间结果 v 的后续编码；接起来之后，收到最终延续 k 时做的是：

m\bigl(\lambda v.\,B(v)\,k\bigr).

这个式子只回答一件事：前一步交出的值怎样进入后面的有名变量。

接着才问：已有的 ∘𝒦 能不能表达这件事？此时引入宏里的 id，并当场展开它的类型：

¬¬a\to_{\mathcal K}a
\quad\text{展开就是}\quad
¬¬a\to_{\mathcal D}¬¬a.

它接收的是整个编码值，并没有从双重否定里取出一个普通的 a。这个解释应该紧贴第一次出现，不能让读者回翻。

然后立即区分：

* 宏里的普通 id，在这里原样传递一个编码值；
* 提前介绍的 cps:id，把普通值交给延续，是 ∘𝒦 的单位。

六步展开则压成三个有意义的中间站：

1. 一个绑定怎样连接前一步与后一步；
2. 两个绑定怎样嵌套出同一条延续链；
3. 用单位律去掉空步骤，用结合律改变分组。

临时变量替换、逐层消去 let、实现细节放到后置推导或完整代码。正文保留基本绑定与递归展开规则即可，不必在这里同时解释全部宏的每个实现细节。

这不是减少论证，而是让每一步论证回答不同的问题。

第三篇：“局部否定下的世界”的动机，应来自运行边界，而不是补齐第二篇的表。

这一节最值得回答的问题其实已经出现在前文：

为什么现在交入 id 就能运行一段计算？内层运行完之后，又怎样接回一个答案类型可能不同的外层？

这个问题有实际悬念，也确实需要区分内外两种答案类型。相比之下，“换了基以后，把所有运算符重新写一遍”主要是在维护体系完整性。

我建议把现有这一大节拆成三部分处理。

* cps 与 cps* 的区别，留在“逃逸与丢弃”。那里有真实失败：本来应当退出的程序继续遍历，最后把 ans 交给乘法。这已经是很好的动机。修复之后，读者已经知道“接着当前工作”与“丢弃当前工作”的区别，后面不必再用另一套表示完整重演。
* “栈的切片”之后，直接接“求值与边界”的核心。从局部工作以 id 结束，得到 eval m = m id；再展开 reset，看外层怎样接过内层答案。
* 局部否定的类型整理，围绕这次接回进行。先用具体的内层答案 a、外层答案 x，再写相应签名。不要先让读者接受抽象的 ∀x，经过几个运算符后才说明它有什么用。

这样，a 与 x 不同的意义是在代码里产生的：

reset(m)(k_{\text{outer}})
=
k_{\text{outer}}(eval(m)).

内层以 a 为答案；得到的 a 又成为外层继续工作的输入。签名此时只是把已经看到的事情写清楚。

可以压缩或移走的内容也很明确：

* neg 的三种签名不必连续列出。保留基本的预复合公式；另两种在实际使用处代入即可。
* 不必同时完整展示 neg:call/lc、neg:call/cc、cps:call/lc、cps:call/cc。正文以已经在运行的 CPS 写法为主；逆否写法可留作练习或完整代码。
* eval 又是三重否定、又等于 cps:id 包装终结延续，这个观察可后置。它不应挡在 eval m = m id 与 reset 的解释之间。
* Peirce／Clavius 的对照可以保留为短暂回看，但不能继续充当本节主线。call/lc 这里只得到终点为 a 的实例，就明确说到这个范围。
* 末尾总表不必再次完整复述所有签名。较完整的表示关系可以留到第二部；不必把删下来的内容全部塞进第六篇。

call/cc 的措辞则应统一到元延续例子已经展示的行为：丢弃调用处当前边界内的剩余工作，完成保存的局部工作后，把答案交给调用时边界外的工作。边界外的加一百还会执行。“一直走到整个程序出口”不能保留为这里的解释。

3. “代数”在哪里兑现，兑现到什么程度

我建议至少有三次明确落点，第一次放在第二篇；不必强迫第一篇提前铺设。

第一次：第二篇 ∘𝒦 构造完成之后。

先造 cps:id，再验证：

\begin{aligned}
id_{\mathcal K}\circ_{\mathcal K}f&=f,\\
f\circ_{\mathcal K}id_{\mathcal K}&=f,\\
h\circ_{\mathcal K}(g\circ_{\mathcal K}f)
&=(h\circ_{\mathcal K}g)\circ_{\mathcal K}f,
\end{aligned}

其中 id_{\mathcal K} 就是 cps:id。

先展示“不增加工作的一步可以消掉”“三步连接可以改括号”，然后才给出单位律、结合律的名字，指出这些就是当前构造的代数规律。限定在这里使用的纯 CPS 接法下即可，不要扩张成完整 Racket 的任意上下文等式。

这已经兑现了标题的第一笔承诺：读者得到的不是一个比喻，而是可以用于后文宏化简的规则。

第二次：第三篇“栈的切片”。

现有这两处实际上非常合适：

(k_a\circ k_{a,q})\circ f
=
k_a\circ(k_{a,q}\circ f),
\qquad
k_a\circ id_a=k_a.

指出：同一条工作链可以重新分组，边界处没有剩余局部工作时用恒等函数结束。此处让第二篇的规律再次产生解释力。

但要保持因果顺序：先有 reset 建立的边界，再用结合律描述两段工作怎样接起来。结合律本身不会建立控制边界。

第三次：第五篇推出 ∘ℒ、化简为 append-map 之后。

这里已经有：

(append-map list v*) 把每项包成列表再接起来，还是原来的 v*。

就地认出单位；再用一个小例子展示三步搜索改变分组但保留枚举次序与重复次数，认出结合律。列表的单位是单元素列表这一步，不能与表示失败的空列表混淆。

到第五篇，读者已经在不同构造里见过相同的规律。第六篇再揭示统一框架，就有东西可供“认出”。

前五篇不需要提前给出抽象的统一接口，更不需要提前引入整套符号。先认识各个构造中的规律，第六篇再认识它们共同的结构。这既符合“先造后认”，也不会让第六篇只剩一个迟到的名称。

4. neg² 的签名：我明确选 𝒟 → 𝒟

对于现有定义：

(define neg² (∘ neg neg))

我建议写成：

neg^2:
(p\to_{\mathcal D}q)
\longrightarrow
(¬¬p\to_{\mathcal D}¬¬q).

展开后：

neg^2(f)(m)(k)
=
m(\lambda x.\,k(f(x))).

它说明得很清楚：原来处理普通值的纯函数 f，现在可以放进双重否定编码里继续使用。它仍然调用 f，完全没有矛盾。

如果输入允许任意带效应的 f，输出就不能据此保证属于 𝒟。“只翻译类型，没有翻译程序”不足以挽救原签名，因为签名已经对产物属于 𝒟 作了承诺。

𝒞 → 𝒟 的方向可以保留，但应属于另一件事：整段程序的翻译。建议用程序变换记号：

e\;\longmapsto\;\llbracket e\rrbracket

表示宏或翻译规则对源程序逐步改写，而不把它写成现有 neg² 包装函数的类型。对高阶程序，输入、输出中的函数类型也需要相应处理，不能把所有翻译概括成给两端各添一个 ¬¬。

这样，正文会有两项各自成立的构造：

* neg²：怎样在编码中使用一个已有的纯函数；
* CPS 翻译：怎样把程序内部的计算与控制组织成显式延续。

我不建议为了保存总图的漂亮路径，让两者继续共用一个身份。

5. 这套方案是否碰到前几轮的数学限制

会碰到，但可以在结构调整中同时守住，不需要堆注意框。

限制	在本方案中的处理
运行时包装不等于纯翻译	neg² 限于纯输入；整段翻译由宏及原语、控制操作的改写承担。包装 display 并不会消除输出效应。
受条件限制的往返不能推出完整宿主中的全面等价	往返论证退出主线的承重位置；编码操作按自身定义建立，不再依赖四世界总图兜底。
答案类型非空不等于定界控制	先通过 reset、捕获、丢弃及运行规则造出边界，再用答案类型解释接口。不是换一个终点字母就获得了边界。
id : ¬¬a →𝒦 a 不是纯的双重否定消去	初次出现即展开为 ¬¬a →𝒟 ¬¬a；与 cps:id 分开解释。
eval m = m id 不是一般的 ¬ₐ¬ₐp → p	明确这里运行的编码，其结果类型与答案类型同为 a。
A-翻译到单延续编码经过特化	保留双延续版本；说明把答案分支的处理固定为所选终结延续后，才省掉这个参数。不能说所有双延续程序都与单延续程序无损互换。
call/lc 只给出固定答案处的 Peirce 实例	简短说明 q=a，不通过把字母改叫 q 宣称一般结果。

尤其是 A-翻译一节，我建议保留它现在的回顾位置。前面已经运行过单延续代码，这里通过双延续版本看清被固定、省略的那条答案路径，是一次有收益的回看。需要收紧的是“从不改变的参数，不必传”所指的范围：它解释这份构造怎样特化，并不宣布整个双延续类型都能这样简化。

这套调整最关键的取舍，是让第二篇以“我终于能写出这样的程序”形成高潮，让第三篇以“我终于知道这段程序怎样结束、怎样接回外层”形成高潮。类型整理服务于这两个结果；代数规律则在连接、化简和分组这些实际动作里出现。
