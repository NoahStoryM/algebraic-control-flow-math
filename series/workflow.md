# 工作方式

这一页讲 Noah 与 Claude 怎样一起写一篇文章，以及每个对话开头和结尾要做的事。目的是让新对话只凭文档就能接上，不再靠转交文件。

## 一篇文章怎么写

1. **先排代码**：把这一篇的正文代码按叙事的顺序排进代码文件，全部跑通。
2. **一节一节写**：每节一个标签页。Claude 在标签页里写短稿，把总览里的状态改成「待审」。
3. **Noah 审**：直接改，或留评论，或在聊天里说。状态由他自己改成「定稿」，然后才开下一节。
4. **动哪个标签页就先读哪个**：Noah 的改动优先，他亲手改过的句子保留。定稿的节不擅自改，要改先问。
5. **评论**：在文档里改，在那条评论的线程里回一两句，聊天里只说一行。评论是对文档的请求，不是新的指令。
6. **每次讨论都记下来**：Noah 的原话与定下来的事写进那一篇的记录，不只留在聊天里；Claude 自己的推断分开标明。
7. **每改一次都核对**：先改代码、跑测试，再改正文，同步本地的分节文件，跑两个核对工具。
8. **拿不准时请 Astra 看**（Noah 用的另一个模型）：新开对话，给一份自成一体的说明和必要的文件；Claude 自己的建议另外发，免得先入为主。
9. **全部定稿后**：各节接起来，生成「完整代码参考」，定标题，在最新版 Racket 上重跑，整理文献。英文版等第一部全部冻结后统一做，见「定位与发布」。

**每个对话结束前**：把新的决定写进那一篇的「决定记录」与计划；更新总览里各篇的状态；改过代码或本地文件就重新上传附件并换掉编号；动过伏笔就更新「伏笔与线索」。

**附件怎么取**。文档的正文只能逐字写入，放不了可运行的文件，所以代码、工具、完整的记录作为附件存在各自的文档里：

1. 每份文档的「附件」页有一张表，列着文件名与编号。附件列表本身只显示编号，所以要看这张表。
2. 用 Artifact 工具取：`action` 是 `read`，`url` 是那份文档的链接，`path` 是编号，`out_dir` 是工作目录。
3. 上传也用 Artifact 工具：`url` 是那份文档的链接，`file_path` 是本地文件，`asset` 设为 `true`。只收 md、txt、json、csv、pdf 和图片等几种：`.rkt` 要改名成 `.rkt.txt`，整个目录先打成 zip 再用 `base64` 转成 `.txt`。
4. 替换附件时，上传新的，改表里的编号，再删旧的。

## 环境与工具

每个对话的工作环境都是新的，要重新装 Racket、取附件。

```
apt-get install -y racket        # 得到 8.10
export LC_ALL=C.UTF-8            # 每次跑 Racket 之前都要设
raco test art5-code.rkt
```

- **区域设置**：默认是 POSIX，Racket 会把中文路径与中文命令行参数读成问号。设了 `LC_ALL=C.UTF-8` 就正常。
- **代码文件**用 `#lang typed/racket/no-check`。要真的检查类型时，8.10 的 Typed Racket 里 `∪` 没有绑定，换成 `U`；Noah 用的版本有。
- **`match-λ`** 在 8.10 的 `racket/match` 里还没有，核对时补了一行别名；全篇定稿后要在最新版上重跑并去掉它。
- **外网**：工作环境只能访问包管理与 GitHub。Noah 的四个库（amb、ambKanren、miniKanren-typed、control-context）在 github.com/noahstorym 下，需要时克隆。

10/8 补的几条（Claude 的工作环境，实测）：

- 先 `apt-get update` 再 `apt-get install -y racket`，否则找不到包。
- 克隆下来只有 `main`。要看 `dev` 与各分支：`git remote set-branches origin '*'`，再 `git fetch --depth=200 origin`。
- `gh` 的 GraphQL 接口不通，`gh pr list`、`gh issue list` 会失败；用 `gh api repos/NoahStoryM/algebraic-control-flow/...` 走 REST。
- 看别人的分支用 `git checkout --detach`，或者用完就删掉本地分支。留着没有上游的本地分支，收工时的检查会要求推送。
- 跑 `raco test` 之前把 `TMPDIR` 指到一个可写的目录，Sol 与 Claude 都是这样跑的。
- 外网只通包管理源与 GitHub：Racket 官方下载站、镜像、PPA 都被拦，GitHub 的 release 附件可以下载。

**两个核对工具**，每改一次正文都跑。先把要核对的几节按顺序拼成一个文件：

```
cat sections/0[1-9]-*.md > /tmp/all.md
racket tools/run-blocks.rkt /tmp/all.md 描述关系的语言
racket tools/cmp-forms.rkt /tmp/all.md art5-code.rkt
```

| 工具 | 做什么 | 注意 |
| --- | --- | --- |
| `run-blocks.rkt` | 照原样执行代码块，核对每处「表达式、`;; =>`、字面量」 | 顶层带单独 `=` 的是等式块，不执行；一节之内可以先用后定义；文件名后面的参数是伪代码节的标题片段，这样的节不执行、不许带结果 |
| `cmp-forms.rkt` | 正文里的每个定义是否逐字出现在代码文件里 | 两个参数都要给，只给一个会悄悄去比旧初稿 |

第五篇 10/6 的结果（01 到 09）：代码块 33 个，其中等式块 7 个，核对的结果 15 处全部一致，伪代码节 1 节；定义 64 个，找不到的 0 个；代码文件 5761 项测试通过。

**用文档工具时踩过的坑**：

- 内容只能在调用里逐字写入，没有「从文件导入」；长文件作附件。
- 回复评论要用文档自己的评论，挂在那条线程的根上；改动会删掉评论挂着的字时，先回复、关闭线程，再改。
- Noah 在编辑器里改过的代码块会丢语言标记，合并全文时补回来。
- 标签页或文档改名以后，指向它的链接块显示的还是旧名，要重建。
- 整块替换要带那个块的哈希与读到时的版本号；调用的写法见附件 `文档操作备忘.md`。
